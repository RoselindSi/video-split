## 1. Introduction

### 1.1 问题

一个人连续操作三分钟，他反复回到同一只锅、同一个工具堆、同一个待修的轮圈。
模型看这段视频时，每一帧都在从像素重新判断「现在在做什么」，
而它自己几分钟前已经判断过同一个状态。

**本文问的是：模型能否利用它自己维护的交互历史来跟踪状态身份，
而不是每次从视觉重新判断。** 形式上

```
n̂_t = f(x_t, M_{t-1})
```

`x_t` 是当前视觉观察，`M_{t-1}` 是从先前观察累积的交互记忆，`n_t` 是当前交互状态。

### 1.2 记忆的层级，以及本文测了哪两层

`M_{t-1}` 可以有不同的结构化程度：

| | 形式 | 本文 |
|---|---|---|
| previous-state cache | `M = (n_{t-1}, last-successor(n_{t-1}))` | **已测** |
| successor graph | `M = N⁺(n_{t-1})` | **已测** |
| episodic retrieval | `M = {(x_i, n_i, n_{i+1})}_{i<t}` | **未测** |

**图在本文中是测量工具，不是方法贡献。** 它是中间那一层的一个实现，
而本文用它来回答「历史带不带信息、需要多结构化、在线能不能用」。

**第三层一次都没有实现、没有测量。** 所以本文**不声称** memory 优于 graph ——
只声称 graph 对这个 regime 过度结构化。这两句不是同一个结论，中间缺一步，
那一步属于未来工作。

### 1.3 三个发现

按因果链而不是按实验编号：

**① 历史带信息，而且是状态条件化的后继身份。**
只用先验排序（无视觉模型、无语言模型，n=116 决策 / 25 录像）：
真可达集 top-1 **80.8%**，均匀先验 41.8%，节点频率 30.8%，
度匹配打乱 44.0%。`Rt − Rs = +36.8%` CI `[+21.0, +49.5]`，
而 `Rs − U = +2.2%` CI 跨零。**度匹配打乱之后一点不剩** ——
信号不在出度、不在频率、不在先验形状，而在「具体哪些状态跟过这一个」。
频率先验甚至**低于**均匀（`F − U = −11.0%`）。
限定在约束真的收窄候选的 81 个决策上，可达集命中 **97.5%**。
（图 3，`results/auditor/interaction_graph_g1b_summary.json`）

**② 不需要完整的图，而且原因是约束多半为空。**
带视觉塔的完整阶梯（n=322 决策 / 49 录像）：visual 0.730、
单条目缓存 0.786、完整可达集 0.789。`support − visual = +0.059`，
但 **`support − cache = +0.0031`，CI 跨零**。
增益的归属是决定性的：多答对的 19 题**全部**来自确定性 regime，
branching / novel / no-support 各 **+0**；而 branching 那 11 题
**视觉单独已经 11/11 全对**。机制在联合 regime 表里：出度 ≥2 的
11 个决策有 **9 个**的可达集已包含全部见过的候选 —— 条件化排除不掉任何东西。
（图 2，`results/auditor/interaction_graph_ladder.json`；
图 1，`results/auditor/b2_egoexo/paper_regime_points.json`）

**③ 在线失败的瓶颈是身份维护，而硬约束是误差放大的那一步。**
四种模式：visual 0.7298、oracle 前驱 0.7857、预测前驱 0.7267、
全自维护 0.6118。但两个细节比这条曲线重要：
**预测前驱的状态分离度 0.972 是四种模式里最高的**（oracle 0.939、visual 0.824），
整体准确率却掉回基线 —— 先验作为分离器是有效的，崩的是喂给它的身份估计；
而 `prior_override` 从 oracle 的 **1** 跳到预测前驱的 **18** ——
一旦前驱要靠估计，先验推翻视觉 18 次而多半推翻错。
（图 5，`results/auditor/interaction_graph_expD_online.json`）

### 1.4 为什么这个 regime 验证不了，而且这不是采样问题

一个转移先验要发挥作用，需要两个性质同时成立：**状态能被稳定复现**，
并且**同一状态存在多个可用后继**。逐 scenario 测量 19 个点
（16 个 Ego-Exo4D scenario、内部 release、2 个人工粗标批次）之后：

- 两条轴**中等负相关**，`Spearman rho = −0.535`（16 个 keystep scenario）；
- 联合区间**稀疏占据，不是空的** —— `First Aid - CPR` 命中 77.3% /
  `|S|≥2` 3.16%，而且它的 10 个 G-branch **零个是空约束**；
- 但**占据者都达不到冻结的每窗口产出**，最高 0.30 对阈值 0.5。

换数据绕不开：冻结判据（2026-09-28 冻结）在 20 个 Ego-Exo4D 烹饪窗口上
打出 NO-GO，人工粗标 G-branch **0**，而失败的子句是 `|S| ≥ 2` 不是计数 ——
54 个决策里可达集一次都没装过两个不同后继。

**换粒度也绕不开，这一条堵的是本文最可能被攻击的那句「标细一点不就有了」。**
修车族动作级 + 强制 id 复用：keystep 粒度 0.00/窗口 → 人工动作级 **0.50**/窗口
（刚好宽端阈值）→ 去掉纯取得工具状态后 **0.00**。
5 个 G-branch 的前驱 **5/5 全是「拿工具」**，标注者写的条件全是工具身份。
这是本项目当初否掉 EPIC 的同一个 transport primitive（EPIC 60.2% 的分叉在
`pick-up`/`put-down`）。而根本原因是一个访问次数：`|S| ≥ 2` 要求前驱
**已被离开两次**，所以必须有状态被访问 **3 次以上** ——
10 条录像里真实状态最多被访问 2 次，**一条都没到 3 次**，
而「拿工具」有 4 条达到 3-4 次。**粒度细化提高的是过渡动作的访问次数，
不是真实状态的复现。**（图 6，`results/auditor/b2_egoexo/b2_bike_fold_r1.json`）

### 1.5 贡献

**C1 交互记忆的诊断框架。** 严格前缀的决策构造 + 三类分型，
在两个数据集、两个域、两个标注者、两个粒度上测出复现与分叉的权衡，
并给出一条不可绕过性结果：细化粒度造出的是过渡原语。

**C2 转移历史带的是状态条件化的后继一致性，不是拓扑。**
信号在成员身份上；但全部增益来自确定性 regime，完整可达集相对单条目缓存无增益，
机制是出度 ≥2 时约束多半为空。语言序列化的记忆接口被排除，
且其表面收益与内容无关。

**C3 在线状态身份维护是瓶颈，硬约束是误差放大的那一步。**

## 2. Setup

### 2.1 交互状态与决策

一条录像是状态序列 `n_1 … n_T`，相邻相同的合并。
第 `t` 个**决策**是「已经看过 `n_1…n_{t-1}`，现在要判 `n_t`」。
候选集 `candidates` 是**已见过的状态集合**，`gold` 是 `n_t`，
若 `n_t` 从未见过则记 `NEW`。

### 2.2 严格前缀，以及为什么它不是形式上的讲究

所有先验只能用 `G_{<t}` —— 由 `n_1…n_{t-1}` 构成的转移多重图。
`S = N⁺(n_{t-1})` 在**更新这一步的边之前**计算，否则这一步的答案会进到
它自己的前缀里。前缀性逐条核对过：**0/322 条决策使用了超出 `G_{<t}` 的边。**

### 2.3 三类决策（`src/auditor/boundary/branch_mine.py`）

```
G-simple   |S| = 1
G-branch   |S| >= 2  且  |S| < |candidates|  且  n_seen >= 3
G-novel    S 非空  且  gold ∉ S
```

**三个子句都要写出来，尤其第二个。** `|S| < |candidates|` 是判断这个图
**是否真的排除了东西**：若可达集已包含全部见过的候选，条件化它什么也排除不掉,
出度再高也不是约束。本文把这种情况单独报成「空约束」，因为它正是
`support ≈ cache` 的机制。

第三个子句 `n_seen >= 3` 的后果值得明说：`|S| >= 2` 要求前驱**已被离开两次**，
所以**某个状态必须被访问 3 次以上**；访问两次只能给出 `|S| = 1`。
这把「状态会复现」这个模糊要求变成了一个可查的计数。

### 2.4 两条轴（`src/auditor/boundary/b2_joint_regime.py`）

**复现**：`P(S 非空)`（前驱是否曾被离开过），以及
`P(gold ∈ S | S 非空)`（图开口时它说对了吗）。
**不是** `P(n_t = n_{t-1})` —— 那是自环率，是原地不动，不是回到做过的状态。

**分叉**：`P(|S| >= 2)`，并报其中空约束的比例。

### 2.5 粒度合同

状态的定义会直接决定上面每一个量，所以它必须可判定：

> **状态 = 作用于什么 + 怎么作用。只为取得手段而存在的移动
> （拿工具、放回工具、整理工具）不建状态，并入它服务的那个动作。**
> 自检：如果一个状态的全部内容就是「为了能做下一件事」，它不是状态。

分界不在动词：`拿充气枪` 折叠，`拿充气枪给轮胎充气` 保留；
**取得零件不折叠** —— 换胎而不是补胎是一个决策。

### 2.6 数据与两个粒度来源

- **内部 release**：49 条录像 / 322 个决策，人工标注合同，
  其中一条是「回到做过的事要选回原代号」—— 这条合同是它复现率 95.6% 的来源。
- **Ego-Exo4D**：16 个 scenario，用数据集自带的 `step_unique_id` 作为状态身份。
  它可能与人类对「回到同一个状态」的判断不一致，但**这个差异无法用数据集自身
  测量**：换成 `step_name`（按名字合并，本应高估复现）后 16 个 scenario 的命中率
  **逐个完全相同**。而唯一的人工重标探针在同一任务族上把复现质量推向了
  **相反**方向（keystep 命中 52.4% → 人工动作级 15.4%）。
  详见 `docs/paper_limitations.md` ②。**不要把它当成已知偏置写进正文。**
- **人工粗标批次**：Ego-Exo4D 烹饪 20 窗口（活动级粒度）、
  修车 10 窗口（动作级 + 强制 id 复用）。

### 2.7 阈值的冻结

B2 的 Go/No-Go 判据在看到任何数据之前冻结（2026-09-28,
`docs/branching_pilot_b2_spec.md`），并写进代码
（`src/auditor/boundary/b2_yield.py`）。本文报告的是对该判据的机械判定，
不在事后调整它。对判据的任何诊断性扩充都在单独的工具里，不改评估器。
