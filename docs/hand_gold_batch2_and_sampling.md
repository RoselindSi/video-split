# 第二批 15 条揭穿的一件事：第一批不是随机样本（2026-10-14）

手级 gold 做到 **25 条录像 / 49 只露过面的手**。合并之后第一件要处理的不是指标，
是两批的可比性。

脚本：`src/semhand/prepare_batch2.py`　结果：`results/semhand/hand_gold/metrics_all25.json`

---

## §1 两批差 21.7 个百分点，而网格缺陷只解释 1.2 点

| | batch1（10 条） | batch2（15 条） |
|---|---|---|
| 来源 | **`fresh20` 的子集，选择判据无记录** | 8622 条随机抽样，种子 20261013，不用模型分 |
| 单一轨迹持有的手 | 31.6% | **53.3%** |
| 覆盖中位 | 94.1% | 98.8% |
| 轨迹数中位 / 切换中位 | 2.0 / 2.0 | **1.0 / 0.0** |

直接测了网格缺陷能解释多少：把 batch2 人为降级成 batch1 的网格
（`sampled_frames` 只留检测器出过框的帧）——

```
覆盖中位 98.8% -> 100.0%   （虚高 +1.2 个百分点）
单一轨迹率 53.3% -> 53.3%  （+0.0）
```

**方向与上界警告一致，但量级只有 1.2 点**，而两批差 21.7 点。
所以差异**不是测量缺陷，是样本**。

batch1 那十条是 `fresh20_jobs.txt` 的子集（旁边就是 `fresh20_handness.json`、
`fresh20_gold_v2.csv`，说明 fresh20 是为 hand-ness gold 选的），
**从 20 条里再挑 10 条，判据没有记录**。

→ **Phase 0/1/2 的全部数字建立在一个选过的样本上，不能当作域的估计。**

## §2 失败构成两批不同

```
窗口 30                 batch1          batch2
  joined_now           12 (28.6%)      6 (21.4%)
  blocked_window       16 (38.1%)     16 (57.1%)
  blocked_ambiguity    12 (28.6%)      2 (7.1%)
  blocked_overlap       2 (4.8%)       4 (14.3%)
  事件总数                 42             28

窗口 150（冻结值）
  blocked_ambiguity    24 (57.1%)     12 (42.9%)
  blocked_overlap       2 (4.8%)       4 (14.3%)
  blocked_distance      0              2 (7.1%)
```

冻结窗口下「歧义是最大的一类」两批都成立，但
**batch2 的重复轨迹占比高三倍**（14.3% vs 4.8%）——
而那一类 `track_join` 结构上修不了（时间重叠硬否，merge-only 做不了取舍）。

## §3 一条要收回的强陈述

之前写过「**只要检测器把框放对了，关联就一定接住了**」，
依据是 batch1 的 `miss_box_unassigned = 0`（519 帧里 0 个）。

batch2 上它是 **6 / 1010 = 0.6%**。量级仍然很小，但不是零。
那句话改成「几乎总是接住」，**「一定」是 batch1 特有的**。

## §4 随机样本上重跑 Phase 0 / Phase 1

**Phase 0**：18 个决策点、54 对（正 27 / 负 27）。比 batch1（35 点 / 111 对）少，
尽管录像多 50% —— 与 batch2 更干净一致。

负例构成差别很大，而这直接影响判据的难度：

| 负例类别 | batch1 | batch2 |
|---|---|---|
| 自己的另一只手（隐私无后果） | 33（61%） | 3（11%） |
| **未归属（可能是别人的手）** | 21（39%） | **24（89%）** |

**Phase 1（纯几何，判据与之前同一条）**：

```
batch1（选过的）  召回 35.1%   误并未归属 1   —— 只差安全约束
batch2（随机）    召回 25.9%   误并未归属 2   —— 召回也不够
```

**两项都没过。** 而且基础更薄：15 条里只有 7 条有可打分的对，
`R26_0827_150022` 一条贡献 54 对里的 24 对（44%）且 AUC 只有 0.562，
其余录像要么没有负例算不了 AUC、要么 n 小到 AUC=1.000 没有意义。

## §5 现在能说和不能说的

**能说**：手级 gold 扩到 25 条，第二批是有记录的随机抽样，present_rate≈1.00。

**不能说**：Phase 2 的「几何+外观召回 54.4%、零污染性误并」是域的性质。
它是在一个选过的、歧义显著更多的样本上测的。
随机样本上的 Phase 2 还没跑（DINOv2 抽特征进行中）。

**合并主指标（25 条 / 49 只手，统一窗口 30）**：

```
>= 50%   44.9%  (22/49)
>= 80%   42.9%  (21/49)
>= 90%   40.8%  (20/49)
>= 95%   34.7%  (17/49)
```

四个阈值**第一次分开**（19 只手时完全相同）—— 出现了「单一轨迹但覆盖不满」
的手，正是旧网格会隐藏的那一类。所以 §6.2 里「主指标只在量碎片化」那个结论
也只对 batch1 成立。

## §6 统一窗口这件事

batch1 的 `detect2_joined` 是 e2e_v4 用**旧窗口 30** 跑的（早于窗口冻结），
batch2 若现在跑就是 150 —— 直接合并等于在比两个不同参数下的系统。

所以两批的 join 都由 `prepare_batch2.py` 按**同一个窗口**重算。
前提是模拟能复现流水线，而这一条核对过：**窗口 30 下 10/10 条与 e2e_v4 实际分组一致**。

# §7 随机样本上的 Phase 2：五个变体全部未过，但原因不是外观（2026-10-14）

```
留一录像，判据与之前同一条（未归属误并 = 0 且 召回 >= 30%）

打分                      召回          误并自手   误并未归属   判据
几何 s_plain              7/27 = 25.9%     0          2       未通过
外观 cos_mean 单独       12/27 = 44.4%     0          1       未通过
外观 cos_junc 单独       14/27 = 51.9%     0          2       未通过
几何 + cos_mean          10/27 = 37.0%     0          3       未通过
几何 + 两个外观          13/27 = 48.1%     0          4       未通过
```

## 7.1 外观信号更强了，不是更弱

```
决策点内 AUC          batch1    batch2
  cos_mean            0.866     0.900
  s_plain（几何）      0.821     0.707
```

按负例类别拆开（我先猜「外观在未归属上弱」—— **数据否定了这个猜测**）：

| 对比 | batch1 | batch2 |
|---|---|---|
| 同一只手 vs 自己的另一只手 | 0.793 | 0.802 |
| 同一只手 vs **未归属** | **0.891** | **0.835** |

外观对「未归属」反而**更强**，两批都是。负例构成不是原因。

## 7.2 真正的原因：零污染的阈值由 3-4 条录像决定

```
全量（能达到的工作点，零污染）      batch1 召回 64.9%    batch2 召回 44.4%
LORO（自动选阈值）                54.4% 污染 0       37.0% 污染 3
```

**两批全量都满足判据。** 差别在阈值能不能跨录像迁移：

```
有「未归属」负例的录像数      batch1  3 / 10      batch2  4 / 15
零污染所需阈值               0.618-0.728        0.556-0.689
极差                        0.109              0.133
```

**整个安全约束建立在 3-4 条录像上。** LORO 要从这几个单位里学一个可迁移的
阈值，学不出来 —— batch1 那三条的阈值恰好够接近、碰巧找到了，batch2 的四条没有。

## 7.3 所以结论变了

**不是**「外观消解器在真实分布上不work」。
**是**「判据的约束项由极少数录像决定，样本量不足以定阈值」。

证据：外观的判别力在两批上一致甚至更好（AUC 0.835-0.900），
全量工作点两批都达标，失败的只有自动选阈值这一步。

**这指向一个采集目标而不是建模目标**：需要更多**含有危险负例的录像** ——
即别人的手或非手候选出现在自己的手附近的录像。
25 条里只有 7 条有这种情况。继续随机抽会很慢（约 28%），
而按「是否含别人的手」筛选又不能用模型分来筛。

这也解释了为什么 Phase 1 在两批上都挂在同一个地方：
它和 Phase 2 共用这个约束，而约束的样本基础从一开始就只有 3-4 条。

# §8 「危险负例」其实是两类，而 batch1 的安全性只测过 1 个（2026-10-14）

人脸信号（`n_faces`，来自独立于手部流水线的人脸模型，已在每条检测 csv 里）
作为筛选规则：命中率从随机的 28% 提到 **50-75%**，但**漏掉 43-57%**。
漏掉的三条（`133848`/`153159`/`063732`）**一帧人脸都没有却含危险负例**。

查下去发现 `unassigned` 这个类把两种东西混在了一起：

| | 条数 | 位置 | 框宽 | 目视确认 |
|---|---|---|---|---|
| ownership 判「别人的」(own=0) | 18 | 集中在**有脸**的录像 | 29-160 px | 真手（蓝手套）|
| ownership 判「自己的」(own=1) | 15 | 集中在**零人脸**的录像 | 249-688 px | **前臂、车身倒影** |

而 hand-ness 闸门判这 33 条**全部是手**（`not_hand = 0/33`）。

目视了 4 个：`153159` tid9 是红色车身上的**手的倒影**，`063732` tid2/tid8 是
**前臂**，`133848` tid10 是**真手（蓝手套）**。前三个都是 own=1 大框，
第四个是 own=0。n=4 很小，但方向一致。

## 8.1 两类的隐私代价完全不同

```
并错别人的手    -> 整条轨迹判成 owner -> 别人的手不打码 -> 灾难
并错前臂/倒影   -> 轨迹脏了，但那是**本人的**前臂 -> 零泄露
```

所以「零未归属误并」这个硬约束**比隐私要求严**，它连没有任何代价的合并也禁止。

## 8.2 但这不是 batch2 挂掉的原因

按 ownership 把两类分开重测（`own` 只作诊断代理，不当真值 ——
那个模型本身只比多数类高 3-4 点）：

```
                        旧判据（全算危险）      新判据（只算真危险）
batch1   召回 54.4%     误并 0  通过          误并 0  通过
batch2   召回 37.0%     误并 3  未通过        误并 3  未通过
```

**batch2 那 3 次污染全在真危险类里**，放宽约束救不了它。

## 8.3 真正的发现：batch1 的安全性只测过一个用例

```
真危险负例数      batch1: 1        batch2: 17
```

**batch1 的「零污染性误并」是在只有一个真危险负例的情况下得到的。**
那不是安全性证据，是样本里几乎没有危险可言。

这也解释了 §1 的 21.7 点差距从何而来：batch1 是为 hand-ness gold 选的，
以单人场景为主，它的 `unassigned` 几乎都是前臂和倒影这类自身误检；
batch2 是随机抽的，真的包含别人在场的录像。

## 8.4 对下一步的影响

Phase 3 的采样规则要分别对准两类，而它们的信号不同：

- **别人的手**：人脸信号有效（命中 50-75% vs 随机 28%），且与手部流水线独立
- **前臂 / 倒影**：与人脸无关，是检测器 + hand-ness 闸门的自身误检；
  它们**不该进入安全约束**，但应该单独报，因为它们污染轨迹

另外 gold 的 schema 现在**表达不了这个区分**：`hand_gold_v1` 只标「本人的两只手」，
凡不是这两只的一律落进 `unassigned`。下一批标注必须加一个字段区分
**「别人的手」/「不是手（前臂、倒影、物体）」**，否则安全约束永远测不准。
