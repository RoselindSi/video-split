# 标注手册 v2

2026-09-24。配合 `interaction_graph_schema_v2.md` 使用。

**你只需要视频和这份手册。** 不要参考任何已有标注、模型输出或别人的答案。
遇到判不了的，用 `uncertain`——它是一个正式取值，不是没填。

---

## 一 先判「是不是交互状态」

对每一段，按顺序问三个问题：

```
1. 有没有一个被作用的具体物体？
2. 有没有施加于它的动作？
3. 有没有在物体或场景上留下的可观察变化？
```

**三个都有 → 交互节点。**

**主要是等待、跟随、巡视、一般位移、遮挡、不可见 → 特殊状态。**
特殊状态照常占据时间轴，**不要删掉它，也不要把它两边的状态接起来**。

**能看到携带物体或位移，但判不出它是独立的目标，还是别的任务里的附带动作 → uncertain。**

> **判据落在你在视频里看到的东西上，不落在描述写得细不细。**
> 同一个视觉事实不应该因为一个人写了目的、另一个人没写，就得到不同的身份。

### 判例：运输

搬东西最难判，因为「拿着东西走」既可能是一件独立的事，也可能只是别的事中间的一步。
判据是**这个窗口里能不能看到取得、送达或放置本身**，不是看他有没有在走。

| 看到什么 | 判什么 | 为什么 |
|---|---|---|
| 空手离开 → 在别处**取到**某件东西 → 抱着它回来 | **交互节点** | 取得这个动作在画面里 |
| 拿着某物走向一处，**目的地和要用它的设备在同一画面里**，随后就在那里用上了 | **交互节点** | 送达和用途都可观察 |
| 拿着某物在走廊里走，画面里**看不到要去哪**，这一段还没结束视频就到头了 | **不确定** | 同一类动作，但这个窗口证据不足 |
| 在场地里来回走动，手里拿着东西但**并没有在操作它**（例如边走边看手机） | **特殊状态** | 物体只是被带着，没有被作用，也没有可见变化 |

第三、四条和前两条的区别**不是动作不同，是证据不同**。
同一个人做同一件事，能看到结果就是交互节点，看不到就是不确定。这正是「不确定」要承载的情形。

> 不要因为你能猜到他大概要去干什么就判成交互节点。**判据是看到，不是推测。**

### 判例：等待与跟随

```
站着等同事把上一道工序做完     → 特殊状态。等待不推进任何任务目标。
跟着别人走到另一个位置         → 特殊状态。没有被作用的物体，没有可见结果。
在场地里巡视但没动任何东西     → 特殊状态。
```

标为特殊状态**不表示**这些行为没有语义，只表示它们不在本研究界定的交互状态范围内。

## 二 再判「重复」

### 2.1 段内往返（单节点重复）

一段之内同一个动作来回做（擦桌子来回擦），标记这一段 `within_node_repeat = true`。

**它是这一次出现的属性，不是一条边。** 不要因为来回了就切成多段，也不要记成 A→A。

### 2.2 同节点再次出现（A→A）

同一个状态**停下来又重新开始**，中间是另一段。记为一条 `self_transition` 边。

> **A→A 只表示状态回来了，不表示开始了一个新实例。**
> 是不是新实例需要另外的完成 / 重置 / 重启证据；没有就标 `uncertain`，不要从拓扑推断。

### 2.3 多节点循环

同一个任务里，某个节点在**隔了至少一个别的节点**之后再次出现：

```
A 拿出塞子 → B 冲洗 → C 放回 → A 拿出塞子
```

注意 `A→B→C` **只做一次也成立为一个任务**，不要求回到 A 才算完成。

## 三 最后判「任务」

任务簇 = 共享一个**直接任务目标**的节点集合。允许只有一个节点。

优先用**看得见的任务上下文**判归属：同一个工件、同一台设备、同一个工位、同一批物料。

**不要用「出现了环」来判定同任务。**

### 判例：跨任务切换与任务回访

假设时间轴是这样：

```
A 装配 → [等待同事] → C 记录信息 → D 继续装配
↑                                  ↑
任务 T1                            任务 T1
```

两件事**同时成立**，不要二选一：

```
直接边   A → C       不成立    中间隔着特殊状态，禁止跨间隔合成
直接边   C → D       成立
任务回访 T1          成立      T1 在时间序上离开后又出现了
```

**特殊状态会切断边，但不会切断任务回访。** 这是 v2 最容易记反的一条。

> 直接边要求**相邻且两端都非特殊状态**；
> 任务回访定义在**时间序的任务出现**上，中间隔一个特殊状态不打断它。

### 判例：环不等于同任务

```
炒菜 → 扫地 → 炒菜
```

这是**任务回访**，不是「炒菜和扫地属于同一个任务」。
拓扑上的环只是结构证据，不能单独判定任务连续。

## 四 三个必须分开的概念

```
A → B → C → A            同一任务内的流程重复     node recurrence
Task1 → Task2 → Task1     任务离开后回访           task recurrence
同一任务的一次具体执行      episode instance
```

- 节点回访 ≠ 同一个 episode
- 自环 ≠ 新 episode
- 多节点环 ≠ 同一个任务
- 属于同一个簇 ≠ 当前是同一次执行

---

## 五 新东西永远允许

- 没见过的状态 → `NEW_NODE`
- 没见过的任务 → `NEW_CLUSTER`
- 没见过的转移 → 照记

已有的边只是**可修正的历史先验**，不是禁止清单。

## 六 填什么

每一段：

```
[t_start, t_end]
类型          interaction_node | special_state | uncertain
node_id       局部匿名（A/B/C…），同一状态复用同一个 ID
object        被作用的物体
interaction   施加的动作
visible_result 可观察的变化
within_node_repeat  true/false
special kind  waiting | following | patrolling | locomotion | occluded | idle | not_started
cluster_id    局部匿名（T1/T2…）
goal_evidence 凭什么判它属于这个任务
confidence    high | medium | low
```

判不了就写 `uncertain` 并在 `note` 里写**你看到了什么、缺了什么**。
缺证据是一个结果，不是一次失败。

---

## 七 本手册已知的边界

- 全部判例来自**单一标注者**的 v1 冻结版，未经人际一致性验证。
- **跨任务切换与任务回访的判例全部来自马赛克补集批次**，重复动作批一条都没有。
  这两类规则目前只有一个批次的证据支持，而两批的转移速度相差三倍。
- 运输类复合状态是否应当拆分**没有规定**。
  「走过去 + 取到 + 搬回来」可以算一个状态，也可以拆成几个；本手册不规定该怎么拆。
  **遇到这类请照你自己的判断标，并在补充说明里写明你是怎么想的**——
  这正是本轮试标要暴露的东西，不是要你猜出一个标准答案。
