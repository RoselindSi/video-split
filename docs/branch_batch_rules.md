## 这一批和之前几批不一样的地方

前几批每条录像 5–7 段，这一批每条十分钟左右，段数多得多。请按时间顺序从头做完一条
再开下一条，不要跳着标。

**这一批之所以被挑出来，是因为里面可能有不止一件事在交替推进。** 人会做一会儿甲、
切去乙、过一阵再回甲。下面几条规则都和这个有关。（具体是哪几件事，以你看到的为准，
不要假设一定有两件。）

### 1. 交替不等于同一个节点

甲 → 乙 → 甲 → 乙 这样来回切，**甲和乙是两个不同的节点**，不要因为它们总是成对
出现就合成一个「甲乙循环」。同样，也不要因为两次做甲之间隔了一个乙，就把两次甲
当成两个不同的节点。

### 2. 重复按 occurrence 记，不按时长

同一个动作连续重复（拧了十下同一个盖子），算**一段**，在段上勾 `within_node_repetition`。
只有出现**可观察的完成、复位或重新开始**时，才算新的一次 occurrence，才切新段。
判据是有没有「脱离」（disengagement），不是重复了多久。

### 3. 回到之前做过的事，用同一个节点名

这是这一批的核心。人切回甲的时候，请把它标成**和之前那次甲同一个节点**，不要
另起一个新名字。措辞飘了会让「回到甲」看起来像「去了一个新地方」。

如果不确定这次和上次是不是同一件事，选 `uncertain`，不要猜一个新名字。

### 4. 特殊状态

等待、跟随、走动、找东西这些，标成**特殊状态**，不是交互节点。特殊状态不参与连边。

### 5. 证据只能来自当前时刻之前

判断「这是之前做过的那件事」时，只能用**到此刻为止**看到的画面。
如果是看到后面才反应过来前面那段是什么，照常标，但在备注里写明是**事后**才确认的。

---

统一规则
1. 同一次任务继续做，包括来回擦、反复拧：不要切段。
2. 同一种事已经结束，之后重新开始：在真正开始处切开，右边继续选择原事件。
3. 目标换了：在新目标真正开始处切开，右边新建或选择另一个事件。
4. 空白等待本身不单独建事件；切点放在后面动作真正开始的位置。
5. 每段都写事件，完整看完后再提交。
