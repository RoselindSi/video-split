# Manuscript 大纲 v2：图是工具，不是贡献（2026-10-12）

取代 `docs/paper_skeleton.md` 的**定位**，保留它的全部表格。两份都留着，
因为「为什么收窄到这里」本身是论文第 6 节要讲的东西。

## 研究问题

旧：*Can graph-based reasoning improve egocentric video understanding?*
→ 太大，而且把一个表示当成了问题。

新：

> **模型能否利用自己维护的交互历史来跟踪第一视角交互状态，
> 而不是每次从视觉重新判断？**

图在这篇论文里是**测量工具**，不是方法贡献。这个改写不是为失败找说法：
四条实验恰好把「交互记忆」这个问题拆成了三层，而图只是其中一层的一个实现。

## 记忆层级（论文的组织骨架）

```
Interaction Memory  M_t
      ├── previous-state cache      M_t = (n_{t-1}, last-successor)      ✅ 已测
      ├── successor graph           M_t = N⁺(n_{t-1})                     ✅ 已测
      └── episodic retrieval        M_t = {(x_i, n_i, n_{i+1})}_{i<t}    ❌ 未测
```

**第三层一次都没测过，大纲里不得出现任何关于它的结论。**（见下「三处纠正」②）

## 三处必须纠正的说法

**① 「cache > support，所以 episodic memory 已经够了」—— 两处错。**
cache **不是**优于 support，是**测不出差别**：`support − cache = +0.0031`，CI 跨零。
而且 cache 是**更弱**的记忆（单条目查表），不是 episodic retrieval。
可支撑的表述只有一句：*单条目后继缓存与完整可达集在当前数据上不可区分*。

**② 记忆层级的顶层是空的。** episodic retrieval 从未实现、从未测量。
它属于 Future work 和 paper 2，不属于 Contribution。

**③ 「transition structure 提供有限但真实的信息，主要来自 successor consistency」
—— 不是「主要」，是「全部」。** ladder 的 regime 分解：

```
support 比 visual 多答对 19 题
  来自 deterministic   +19
  来自 branching        +0      ← 这里只有 11 题，而 visual 单独已经 11/11
  来自 novel            +0
  来自 no-support       +0
```

写「mostly」会被追问；写「entirely，而且结构本该起作用的那 11 题视觉已经满分」
才是数据说的话。

## 章节骨架

### 1. Introduction

动机：长视频里的交互状态是否有持续身份；模型能否复用自己的转移经验。
三层记忆，三个层次的问题：历史有用吗 → 需要多结构化 → 在线能用吗。

### 2. Setup

状态身份、严格前缀的决策构造、`classify` 的三类
（`src/auditor/boundary/branch_mine.py`）。
`G-branch` 三个子句都要写出来，尤其 `|S| < |candidates|`——
**出度高但允许全部候选的图不是约束**。前缀性已逐条核对：
`0/322` 条决策使用了超出 `G_<t` 的边。

### 3. 表示层：历史以什么形式进入模型（E1b / E2）

**Result 1（E1b，307 个 oracle 边界候选）：同一个关系问题，表示决定偏置方向。**
看视频 → 视觉连续性偏置 → 偏向 `SAME`；看文本 → 措辞差异偏置 → 偏向 `DIFFERENT`。
推论写成方法论要求：**任何单一表示的关系结论都带这个偏置，必须成对读。**

**Result 2（E2，表示消融阶梯）：文本序列化测到的是上下文长度和排版，不是结构。**
长度与结构在 M0..M3raw 完全共线；拆开后 **结构 ≈ −4 点（不显著）、长度 ≈ −15 点**。
唯一的正面效应挂在「一行一个节点的紧凑字典」这种**格式**上，而且**与内容无关**：

```
标签随机置换      +0.7%
无意义占位符      +2.6%
```

`M2raw` 最初那个 **+20.4%** 是混淆——字典用了 canonical（oracle）名；
加 `M2rawd` 后 **−6.6%，CI 跨 0**。

这一节的作用：**把「历史序列化成文本」这个记忆接口排除掉**，
而且排除得比「效果不好」更强——它的表面收益不依赖记忆里写了什么。

### 4. 结构层：图带的信息是什么（G1 / G1b / ladder）

**Result 3（n=116，只用先验排序）：信号在成员身份上。**

| 先验 | top-1 |
|---|---|
| 均匀 | 41.8% |
| 节点频率 | 30.8% |
| **真可达集** | **80.8%** |
| 度匹配打乱 | 44.0% |

`Rt − Rs = +36.8%` [+21.0, +49.5]；`Rs − U = +2.2%`（CI 跨 0）。
**度匹配打乱之后一点不剩** → 不是出度、不是频率、不是先验的形状，
而是「具体哪些状态跟过这一个」。**频率先验（30.8%）低于均匀**，
转移频次的贡献不成立。

这正是新表述要的那个量：`m(n_{t-1})` 这种**状态条件化**的记忆。

**ladder（n=322 / 49 录像，带视觉塔）：**

| regime | n | 占比 | visual | cache | support |
|---|---|---|---|---|---|
| no-support | 117 | 36.3% | 0.607 | 0.607 | 0.607 |
| deterministic | 185 | 57.5% | 0.784 | 0.881 | 0.886 |
| branching | 11 | 3.4% | **1.000** | 1.000 | 1.000 |
| novel | 9 | 2.8% | 0.889 | 0.889 | 0.889 |
| 整体 | 322 | | 0.730 | 0.786 | **0.789** |

`support − visual = +0.059`；`support − cache = +0.0031`（CI 跨零）。
**19 题增益全部来自 deterministic；branching 那 11 题视觉已满分。**

**写法警告：** `self / recency / frequency` 三臂的 0.7298 **不是三个独立结果**
——CV 把 λ 选成 0，打分式退化成 `cos(x,μ)`，与 visual **逐位相同**。
正确表述是「没有任何权重能提升留出准确率，CV 因此归零」。
`shuffled`（λ=0.02，0.7298）是有效控制，可以报。

**负向简化（主动回答 "Why do you need a graph?"）：** 在当前数据上不需要。
`previous state → 缓存的后继 + 当前视觉证据` 就够了。
而机制在下一节：不是「因为确定性」，是**因为约束多半为空**。

### 5. 结构为什么退化成记忆（joint regime）

同一个 `classify`、同一套严格前缀，两条轴分开报
（`src/auditor/boundary/b2_joint_regime.py`）：

| 数据 | 单位 | 决策 | S 非空 | 命中\|S非空 | \|S\|≥2 | 其中空约束 | G-branch |
|---|---|---|---|---|---|---|---|
| 内部 release | 49 | 322 | 63.7% | **95.6%** | 3.42% | **9/11** | **0.62%** |
| Ego-Exo4D 烹饪 keystep | 20 | 240 | 15.8% | 10.5% | 3.75% | 0/9 | 3.75% |
| Ego-Exo4D 烹饪 keystep（另一抽样） | 30 | 397 | 19.4% | 33.8% | 4.79% | 0/19 | 4.79% |
| Ego-Exo4D 抗原 keystep | 30 | 356 | 19.1% | 10.3% | 4.78% | 0/17 | 4.78% |
| Ego-Exo4D 修车 keystep | 30 | 162 | 13.0% | **52.4%** | **0.00%** | — | 0.00% |

三件事：

**① 结构退化的机制是「约束为空」，不只是「确定性」。** 内部数据里出度 ≥2 的
11 个决策有 **9 个**的可达集已包含全部见过的候选——条件化排除不掉任何东西。
`support ≈ cache` 的原因在这里，而不是一个 null。

**② 两条轴反相关。** 内部：复现 95.6% / 可用分叉 0.62%；
Ego-Exo4D 烹饪：10.5% / 3.75%；修车：52.4% / **0.00%**。
高复现的两族（内部、修车）分叉最少。
**可以有复现而无分叉，或有名义分叉而无复现，拿不到两者同时成立。**

**③ 单次抽样方差很大，图上不能画成一个点。** 同一个烹饪族两次均匀抽样，
命中率 10.5% 对 33.8%（n=38 对 n=77，CI 不重叠）。各 scenario 产出从 0.02 到 1.05。
主图 `docs/paper_joint_regime_figure.svg` 的 Ego-Exo4D 点要带不确定性。

### 6. 这个 regime 能不能靠换数据或换粒度绕开（B2）

**换数据：** 冻结判据（`docs/branching_pilot_b2_spec.md`，2026-09-28 冻结）在
20 个 Ego-Exo4D 烹饪窗口上打出 **NO-GO**：人工粗标 G-branch **0**，阈值 15。
失败的子句是 `|S| ≥ 2` 而不是计数——54 个决策里可达集一次都没有装过两个不同后继。
粗标 0 / keystep 9，两个粒度都是个位数。

**换粒度：** 第三轮修车族动作级 + 强制 id 复用
（`docs/branching_pilot_b2_round3_result.md`）：

```
keystep 粒度          G-branch 0.00 /窗口
人工动作级（如实计）   G-branch 0.50 /窗口   ← 刚好宽端阈值
去掉纯取得工具状态后   G-branch 0.00 /窗口
```

5 个 G-branch 的前驱 **5/5 全是 `拿工具`**，标注者写的 condition 全是工具身份。
这是本项目当初否掉 EPIC 的同一个 transport primitive
（EPIC 60.2% 分叉在 `pick-up`/`put-down`），只不过这次由我们自己的细化产生。

**最该进正文的是访问次数判据：** `|S| ≥ 2` 要求前驱已被离开**两次**，
所以必须有状态被访问 **3 次以上**；访问两次只给 `|S| = 1`。

```
真实状态最大访问次数   1 次 6 条 / 2 次 4 条 / >=3 次 0 条
「拿工具」             >=3 次 4 条，最多 4 次
```

**粒度细化提高的是过渡动作的访问次数，不是真实状态的复现。** 并且产出率
可以靠把过渡动作切得更碎无限刷高（`拿工具` → 伸手/握住/抬起），
所以产出率本身不能作为「域里有 branching」的证据。

这一节堵掉的是整篇论文最可能被攻击的那一句：**「标细一点不就有了？」**

### 7. 在线层：瓶颈是身份维护，不是转移模型（Experiment D）

n=322 / 49 录像，四种模式：

| 模式 | identity top-1 | diff-state separated | prior_override |
|---|---|---|---|
| visual | 0.7298 | 0.824 | 0 |
| oracle 前驱 | **0.7857** | 0.939 | 1 |
| 预测前驱 | 0.7267 | **0.972** | 18 |
| 全自维护 | **0.6118** | 0.818 | — |

**不要只写「在线崩了」。两个细节才是 Contribution 3：**

**① 先验作为分离器是有效的，崩的是喂给它的身份估计。**
预测前驱那一列 `diff_state_separated` **升到 0.972（最高）**，
整体准确率却掉回基线。

**② 把先验做成硬约束，是身份误差转成预测误差的那一步。**
`prior_override` 从 oracle 的 **1** 跳到预测前驱的 **18**。
oracle 几乎从不推翻视觉；一旦前驱要靠估计，它推翻 18 次，而推翻多半是错的。

这两条直接指向 paper 2 的方法形态：**记忆要以软检索而非硬约束进入**，
并且要容许当前状态不确定。

### 8. 评测协议应该量什么（Contribution 3 的落点）

不是只测 action segmentation，而是四件事，都有现成工具：

1. **状态复现率** —— `S` 非空的比例，以及 `S` 非空时 gold 在里面的比例
2. **可用分叉率** —— `|S| ≥ 2` 且真的收窄了候选（**空约束那一列必须报**）
3. **在线身份稳定性** —— `prior_override` 与 `diff_state_separated` 成对读
4. **粒度合规** —— 状态 = 作用于什么 + 怎么作用；只为取得手段而存在的移动不建状态

工具：`b2_joint_regime.py`、`b2_grain_compare.py`、`b2_grain_fold.py`、
`g1_ladder.py`、`g1_online.py`。

## Contributions（按新定位）

**C1. 时间状态持续性的诊断框架。** 给出一套严格前缀的决策构造与三类分型，
并用它在两个数据集、两个域、两个标注者、两个粒度上测出：**复现与分叉反相关**，
而评估结构化转移先验需要两者同时成立。附带一条**不可绕过性**结果：
细化粒度造出的是 transport primitive，真实状态的复现次数不随粒度增加。

**C2. 转移结构带的信息是状态条件化的后继一致性，而不是拓扑。**
信号在成员身份上（度匹配打乱后归零，`Rt − Rs = +36.8%`），
但全部增益来自确定性 regime，且完整可达集相对单条目缓存**无增益**
（`+0.003`，CI 跨零），机制是出度 ≥2 时约束多半为空（9/11）。
文本序列化的记忆接口被排除，且其表面收益与内容无关。

**C3. 在线状态身份维护是瓶颈，硬约束是误差放大的那一步。**
oracle 前驱 `+0.056`，预测前驱归零，全自维护 `−0.118`；
而预测前驱的状态分离度反而最高（0.972），`prior_override` 从 1 升到 18。

## Paper 2（未来，不进这篇）

**Persistent Interaction Memory**：`p(n_{t+1} | z_t, M_t)`，
记忆以软检索进入、容许当前状态不确定、允许多假设与部分匹配。
