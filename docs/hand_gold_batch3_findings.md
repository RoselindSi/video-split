# batch3 收口：14 份 v2 gold，以及这一轮发现的问题

14 条录像、每条 40 帧抽样格、518 个「佩戴者两只手之外」的候选框全部判过
（443 other_hand / 72 not_hand / 3 unsure），`others_complete_frames` 全部 40/40。

这份文档记的是**问题**，不是成果。其中一半是我自己的测量错误——它们比数据问题更值得写下来，
因为同一类错误在这一轮里重复了三次。

---

## 一、我犯的测量错误

### 1. 把一个从没对着图像核过的数值当成变量

batch3 的选片和整张关系表都用 `detect2` 的 `n_faces` 当「有脸」信号。
R26_0831_134109 报 42%（400 帧里 331 帧）。标注者说一帧脸都没有；把检测器声称有脸的帧
抠出来看——**没有脸**，只有佩戴者自己的双手和白桌面。331 次检测的大小死死卡在
`biggest_face` 0.0038–0.0057（≈115px），是固定浅色物体。

代价：一行错值在 n=9 上把 Spearman 从 0.953 拉到 0.783。

### 2. 修补时又用了一个没核过的数值当锚点

发现 1 之后我定了大小阈值 0.010，两个锚点是：134109 已证伪的误检簇（看过图），
和「R26_0826_102657 的 0.0198–0.0821 是真脸」。**后面这句是断言，我从没看过。**
当天抠帧：也没有脸，实验台加自己戴手套的双手，误检大小 272–545px，**全在阈值之上**。

于是已验证的误检横跨 105–545px，已验证的真脸**一个都没有**，不存在能分开的大小阈值。
阈值和基于它冻结的三条前瞻预测当天作废。

**这是同一个错误在相邻两层上连犯。**

### 3. 把「近乎必然」说成「几何必然」

在 11 条上量出「别人的手 0/398 个框碰下边缘」，我写成了第一视角几何的必然。
第 13 条 R26_0825_183156 帧 720 就有一个（y1=1515，有人走近时手压到下沿）。
改成 **1/426 = 0.23%**。罕见，但不是零。

### 4. 对着错误的目标打分（最严重，它让两个结论反转）

我一直拿 `other_hand >= 1` 当选片目标。真正要找的是**能不能被 `track_join` 并进来**。
用 join 自己的 `DIST_FACTOR=3.0` 量：**443 个别人的手只有 312 个够得着（0.70）**，
分布极不均匀——113022 是 0.92，115154 只有 0.11，**141519 是 0.00**。

后果：我先后宣布两个信号被证伪，两次都错。

| 录像 | 危险负例 | other_hand | 我当时说 |
|---|---:|---:|---|
| R26_0828_141519 | **0** | 5 | 「打破了计数信号」 |
| R26_0825_153426 | **0** | 0 | 「打破了边缘筛子」 |

两条在正确目标下都是**真负例**。计数信号从来没坏；弱的是边缘筛子，
因为它多抓到的恰好是「别人的手太远、并不进来」的录像。

这是定义错误不是调参错误，所以它让结论**反转**而不是偏移。

### 5. 一次静默空跑的检查

`SIX="113022 110805 ..."` 加 `for r in $SIX` —— zsh 不做词分割，循环只跑一次、
拿整个字符串去 grep，于是「六条在仓库里都查不到」是假的。
下一次用数组重跑，六条全部命中。（同族前例：查了个恒等式等于没查。）

### 6. 标志位在单个观测上误报

`size_is_flat`（大小几乎不变 = 固定误检物的签名）在 170216 上触发，
因为那条格子里**只有一帧**有脸——单个观测恒为「扁平」。已改成至少 3 帧才判。

## 二、数据与环境问题

### 7. 人脸检测器有整段录像级的误检

三条能验证的录像（134109 / 102657 / 170216）**每一个人脸检测都是误检**，
大小从 105px 到 545px 横跨整个量程。注意这三条恰好 `other_hand` 都是 0，
而有确认别人的手的那几条查不到帧，所以不能推广成「脸信号整体是噪声」。

### 8. 脸这一列不可延续

决定性的理由不是不准：**流水线不再打马赛克，`n_faces` 以后根本不会产生**。
我是在一个正被拆掉的阶段的副产物上建选片信号。加上脸和手没有必然关系
（有脸但手不进画面 / 手进画面但脸不进）。脸线关闭。

### 9. 六条 detect2 csv 不可恢复

随 scratchpad 清理一起消失；全盘搜索无副本；服务器上也没有（无仓库、无 semhand 产物）。
影响：这六条的有脸率**永远无法验证**，关系表里 8/14 行是未核的。

### 10. 手画的框会超出画面边界

累计 10+ 个，最远到 y=1593 / x=1942（画面是 1920×1520）。不影响判定，但页面该加 clamp。

### 11. 服务器环境

`/scratch` 100% 满（8.0T 零剩余）；`/data/storage` 在这台机器上不存在
（HARD RULE 里的默认产物路径对不上）；可用的是 `/shared`（34T）。
堡垒机一度拒绝端口转发（资产授权侧），后自行恢复。

## 三、方法论层面的发现

### 12. `other_hand` 不等于错误接入（而且我的第一次修正也是错的）

一只 15px 的手在 y=170、佩戴者的手在 y=1400，`track_join` 根本没有可做错的决策。
所以我把目标从 `other_hand >= 1` 改成「`DIST_FACTOR=3.0` 下够得着」。

**这个修正本身也不对。** 距离条件不是 join 判据的主体。读 `forced_pairs`
（src/rig/track_join.py:133-156），真实判据是四条：

1. `gap = b.first - a.last`，**`gap <= 0` 硬否**——时间重叠的轨迹永不合并
2. `gap <= 150` 帧
3. 距离是 **a 末框中心 → b 首框中心**，阈值 `3.0 × width(a 末框)`（只用 x 宽，不是 max 边）
4. **候选恰好一个**，否则弃权

我算的是「同一帧内、两框中心距、尺度取两框 max 边」。逐条对不上，而第 1 条是致命的：
**同一帧出现 = 轨迹时间重叠 = 被硬否**。

量出来：**443 个别人的手里 424 个（96%）出现在佩戴者的手也可见的帧上**，
只剩 19 个有资格进入距离判断，分布在 **3 条录像**（115154 九个、133140 九个、141519 一个）。
191 个别人的手的 113022，有资格的是 **0**。

两个筛子对这个目标一起塌：

```
多余候选 >= 20    TP 2 FN 1 FP 5 TN 6   精度 0.29  召回 0.67
贴侧/上边 >= 1    TP 3 FN 0 FP 7 TN 4   精度 0.30  召回 1.00
（对照：用错误目标时报的是 精度 1.00 / 召回 0.88）
```

**19 是下界。** 硬否作用在**轨迹 span** 上，而我用的是 gold 的手部 intervals ——
那是最粗最长的 span。tracker 实际把佩戴者的手切碎（中位 2.5 倍、42% 有洞），
span 一短，重叠机会就少，有资格的候选只会**变多**。真值要靠带 `tid` 的 `detect2`。

**最该记住的**：batch3 里真正的现象比 443 这个数字显示的少得多 —— 3/14 条录像、19 个候选。
这与 batch1 独立得出的「危险负例只集中在 3-4 条录像里」是同一个形状，
而那次的结论是：**这是采集目标，不是建模目标。**

### 13. 富集本身不是问题，不知道选择概率才是

batch1 不能当域估计，根子从来不是「做了富集」，而是**选片判据没有记录**。
只要规则是写死的、并且**对被筛掉的那一层也抽样标注**，按 1/选择概率加权就能恢复域估计。
被排除层的标注不是浪费——它是估计 FN 率的唯一来源，而 FN 率现在完全不知道
（14 条里召回 0.88，但正例只有 8 个）。

### 14. 目标已重新定义（2026-10-15 定）

**不再打码，隐私泄露不再是本 pipeline 的优化目标或错误成本。**
但这不等于别人的手可以随意并入——要按它对**机械臂训练数据**的影响判断。

| 项目 | 后续定义 |
|---|---|
| 要检测的问题 | 错框被 `track_join` 接入目标手轨迹，造成身份或轨迹污染 |
| `other_hand` | 保留为错误来源标签，不再赋予「隐私灾难」成本 |
| `not_hand` / 自己前臂 | 同样按错误接入及其训练影响评估 |
| 别人的手出现但距离很远 | **不能仅凭出现就判定录像有问题** |
| `n_faces` | 从后续筛选规则中移除 |

取消的是**隐私优先级**，不是已经证明所有错框危害相同。别人的手可能导致身份切换，
前臂框可能造成定位偏移；实际严重程度取决于**污染持续时间、轨迹是否被替换、
以及这些轨迹如何进入训练**。当前统一统计「非目标框错误接入」，保留来源标签供后续分析。

**指标分层**：

- **主指标**：实际被接入的非目标框比例；受污染的目标轨迹比例。
- **辅助指标**：满足距离条件的非目标候选数，只用来**筛选值得复核的录像**。
- **错误类型**：`other_hand` / 前臂 / 其他物体分别保留，**不预设成本权重**。

术语随之收紧：`DIST_FACTOR=3.0` 下的那批不叫「够得着」，叫
**「满足距离条件的潜在错误接入候选」**——而且如第 12 条所示，距离条件只是四条判据之一，
单独用它会把 96% 本该被时间重叠硬否的框算进来。

## 四、下一步

**主指标现在算不出来**：它需要带 `tid` 的 `detect2` 来重建真实轨迹 span，
再跑一遍 `forced_pairs` / `join_to_fixed_point`，看哪些合并真的把非目标框拉进了目标轨迹。
本地只剩 6 条 csv，且全是信息量低的；服务器可达但没有仓库和产物（代码走 git bundle）。
**所以第一件事是重建这 14 条的 detect2。**

有了它才能：
1. 算主指标（实际接入比例 / 受污染轨迹比例），而不是停在候选数上。
2. 把 19 这个下界变成真值——佩戴者轨迹的碎片化程度直接决定它。
3. 用真实 span 重新评估辅助筛子，现有两个在正确目标下精度只有 0.29 / 0.30。

选片仍然只有一条干净路：**随机**抽录像（不许用脸或任何模型分），**两层都标**，
按 1/选择概率加权。富集本身不是问题，**不知道选择概率**才是。

附：本轮三个选片信号的死法各不相同，但共同点是都建在检测器输出上，
因而继承检测器的误检；而误检不是均匀分布的，它恰好集中在筛子要看的地方。
