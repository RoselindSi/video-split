# hand_gold v2：把「不是本人的手」劈成两类（2026-10-14）

v1 只标本人的两只手，凡不是这两只的一律落进同一个 `unassigned` 桶。
目视确认过那个桶里混着**代价完全不同的两种东西**：

| | 目视到的 | 并错的代价 |
|---|---|---|
| **别人的手** | `133848` tid10 蓝手套的真手 | 整条轨迹判成 owner → 别人的手不打码 → **灾难** |
| **不是手** | `153159` tid9 红色车身上手的**倒影**；`063732` tid2/8 **前臂** | 轨迹脏了，但那是本人的前臂 → **零泄露** |

安全判据只该约束前者。v1 表达不了这个区分，于是：

- batch1 的「零污染性误并」其实只有 **1 个**真危险负例做测试（另外 20 个是前臂/倒影）
- 那不是安全性证据

---

## §1 v2 加了什么

```json
{
  "schema_version": "hand_gold_v2",
  "hands": [...],                    // 不变：本人的 A / B
  "others": [                        // 新增：A/B 之外的每个候选框
    {"frame": 410, "box": [...], "kind": "other_hand"},
    {"frame": 410, "box": [...], "kind": "not_hand"},
    {"frame": 420, "box": [...], "kind": "unsure"}
  ],
  "others_complete_frames": [400, 410, ...]   // 新增：这些帧的候选框判全了
}
```

**`others_complete_frames` 是必需的，不是冗余。** 没有它就分不清
「这一帧没有别的框」和「标注者还没判到这一帧」—— 而那正是分母会被悄悄改小的
地方，这个项目已经为同类错误付过代价（暴露率分母、census 抽样框、网格被检测过滤）。

---

## §2 标注成本（先量再设计）

25 条录像 / 891 个抽样帧上实测，A/B 之外还剩多少候选框要判：

```
0 个: 606 帧 (68%)      <- 什么都不用做
1 个: 130 帧 (15%)
2 个:  86 帧 (10%)
3 个:  25 帧 (3%)
4+ 个: 44 帧 (5%)
合计 572 个框 / 25 条录像 = 每条约 23 个
```

**68% 的帧零负担**，所以逐帧逐候选是可行的，不必退到轨迹级
（轨迹级还会把 gold 重新键回流水线的 tid 上，那正是 v1 修掉的原罪）。

---

## §3 页面交互

标完 A/B 后按 **O** 进「其他框」模式，点一个候选框在
`别人的手 → 不是手 → 不确定 → 清除` 之间循环。颜色 + 框上文字标出当前判定，
顶部常驻 `其他框：还剩 N 个要判`，N=0 时该帧才进 `others_complete_frames`。

字号 52（1920 坐标系，页面缩到约 480px 宽时约合 13px）+ 黑色描边光晕 ——
这些框常落在车间、货架这类杂乱背景上，纯色字读不出来。

**验证过**：模拟一轮真实标注，A/B 指认把提示从「还剩 4 个」降到「还剩 2 个」，
O 模式循环产出 `other_hand` 与 `not_hand`，导出是 v2、`others` 两条、
该帧进了 `others_complete_frames`。

---

## §4 下游怎么读

`ambiguity_benchmark.py` 现在按轨迹多数票到 `others` 里查 kind，
并把这三类**排除出可用对**（而不是当负例）：

```
unsure                  标注者判不准
unassigned_unlabelled   v2 gold 但这条轨迹一帧都没被判过
blind_no_anchor         一个 anchor 帧都没盖住 —— 没机会被匹配
```

把它们当负例等于把「标注没覆盖到」记成「模型该说不」。

v1 的 gold 仍然跑得通，只是它的负例落在 `unassigned` 里、**口径是混的**，
下游要知道那批不能用于安全判据。

---

## §5 已标的 25 条怎么办

**不回填。** 用 ownership 模型的 `own` 去推 kind 是用模型输出补 gold，
而那个模型本身只比多数类高 3-4 点。已有 25 条保持 v1，
它们能测碎片化与召回，**不能测安全性**。

安全判据要等 v2 的新批次。

# §6 头三份 v2 gold：schema 立刻证明了自己（2026-10-14）

| 录像 | 窗口内有脸 | `other_hand`（并错=泄露） | `not_hand`（零泄露） |
|---|---|---|---|
| `R26_0826_110805` | 92% | **77** | 0 |
| `R26_0825_113216` | 10% | 3 | **9** |
| `R26_0828_124431` | **3%**（筛选脱节） | **0** | 6 |

**在 v1 下前两条会报成「80 个 unassigned」和「12 个」，而真实安全压力差 25 倍。**

第三条印证了窗口对齐检查：它是筛选与标注窗口脱节的三条之一（全片有脸但窗口内
只有 3%），标出来果然**一个别人的手都没有**。预测与结果一致。

框的尺寸也和既有测量对上：`113216` 的 `not_hand` 跨度 600-700 px（前臂/物体），
3 个 `other_hand` 只有 **40-47 px 宽** —— 与 `detector-recall-on-other-hands`
记的「别人的手中位 87px」、`handness-collapses-on-small-boxes` 记的
「小框上 hand-ness 失效」是同一回事。

## §6.1 标到第三条就暴露的一个设计缺口

`124431` 帧 680 有**同一个框（IoU=1.0）既被指认为手 A、又被判成 `not_hand``**。

这不是噪声是矛盾，而且代价明确：那个框会**同时进正例和负例** ——
在安全判据里既算「本该并」又算「并错了就是污染」，把那个事件变成必败。

根因是我的设计缺口：A/B 指认与「其他框」判定是两条**互不排斥**的记录。
页面现在双向堵上：

- 指认为手时，自动清掉这个框在 `others` 里的判定
- 已经是 A/B 的框不接受「其他框」判定，并提示「先清除再判」

已标的那份按「**手的指认优先**」修正（手的指认是主任务、信息更强），
并在文件里留了 `note_fix` 说明改动。

## §6.2 校验器

`src/semhand/validate_v2_gold.py`，每份 gold 入库前跑。现在查六件事：

```
schema 版本 / 手 anchors 与手画数 / others 分类计数
未判全的帧            —— 分不清「没有别的框」和「还没判」
others 帧不在网格里
有标注却不在 complete  —— 自相矛盾
同一个框既是手又被判 others（IoU >= 0.9）  <- 第三条就抓到一次
```

**在 n=3 时抓到，而不是攒到 15 份之后。**
