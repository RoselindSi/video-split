# 标注手册 v2.1

2026-09-26。配合 `interaction_graph_schema_v2_1.md`。

**你只需要视频和这份手册。** 不要参考任何已有标注、模型输出或别人的答案。
判不了的写 `uncertain`——它是一个正式取值，不是没填完。

---

## 一 先判「是不是交互状态」

对每一段问三个问题，**全部只看画面**：

```
1. 能不能确定一个被作用的具体物体？
2. 看不看得到施加于它的动作？
3. 看不看得到留在物体或场景上的变化？
```

**三个都有 → 交互节点。**
**主要是等待、跟随、巡视、一般位移、遮挡、不可见 → 特殊状态。** 照样占时间轴，不要删。
**看得到物体和动作，但看不到结果，判不出它是独立的一件事还是别的事中间的一步 → 不确定。**

> 你推测的目的写在「推测的目的」栏。**它不能让一段成立为交互节点。**

### 为什么把「看到的结果」和「推测的目的」分开

上一轮有人在结果栏写了「选择到合适的摩托车」——那是推测，不是看到的东西。
画面里只有一个人拿着手机在电动车之间走动，没有任何挑选或确定的动作。

正确的填法：

```
看到的动作    手持手机在电动车之间走动
看到的结果    无可观察的挑选或确定动作
推测的目的    可能在挑选电动车
→ 没有可观察结果 → 不成立为交互节点 → 特殊状态 / 巡视
```

**看不到结果就写「无可观察结果」，不要留空，也不要用推测去填。**

## 二 运输：三条各自要查的证据

搬东西最难判。不要问「他是不是有目的」，问这三条：

| 要查什么 | 看什么 |
|---|---|
| **物体** | 能不能确定被运输的是什么东西 |
| **运输过程** | 看不看得到主动的取得、移动、交付或放置 |
| **结果** | 有没有看到送达、放置、移交，或者进入后续操作 |

```
三条都有         →  交互节点
前两条有、第三条无  →  不确定
物体不明、纯位移   →  特殊状态
```

**这三条要按顺序问，不能跳步：**

```
第一步  能不能确定一个被搬动的具体物体？
        不能 → 特殊状态 / 一般位移
        能   → 进第二步

第二步  看不看得到结果（送达、放置、移交、进入后续操作）？
        看得到 → 交互节点
        看不到 → 不确定
```

> **「一般位移」指的是没有任何物体被作用的移动。**
> 手里拿着一个能看清的东西在走，**不算一般位移**——它有物体，必须走第二步。
> 「拿着某物在走，但看不到送到哪、也看不到拿去干什么」的正确答案是**不确定**，
> 不是特殊状态。这是上一轮最容易走偏的一处。

判例：

| 看到什么 | 判什么 |
|---|---|
| 拿着某物走向一处，**目的地在同一画面里**，随后就在那里用上了 | 交互节点 |
| 空手离开 → 在别处**取到**某物 → 抱着它回来 | 交互节点（取得可见） |
| 拿着某物在走廊里走，**看不到要去哪**，这一段还没结束视频就到头了 | **不确定** |
| 在场地里走动，手里拿着东西但并没有在操作它 | 特殊状态 |

第三条和前两条的区别**不是动作不同，是证据不同**。这正是「不确定」要承载的情形。

### 用到了「后来才发生的事」要勾出来

如果你是靠**这一段结束之后**才出现的画面才下的判断——比如「他后来用这个杯子称重了，
所以刚才那段是在运送杯子」——请勾上「**这个判断用到了本段结束之后才出现的证据**」。

原因：模型在线预测时走到那一刻，是看不到后面的。不勾出来，人工图就会用未来的结果
去确定一个当时无法确定的节点，而模型永远追不上。**勾了不扣分，这只是记录。**

每个交互节点还要填「**证据出现在第几秒**」，可以点按钮用当前播放位置。

## 三 重复：只有一种记法（v2.1 改了）

上一轮这里是最大的分歧来源——合同同时允许「一段带反复标记」和「逐轮切开」，
结果两个人各选一种，44 个边界差异里有 18 个出在这上面。**现在只允许一种。**

> **同一交互状态内部的连续重复，不切段。**
> 只有看得到**完成 / 放下 / 重新开始**时，才切开成同一个事件的下一次。

```
来回擦桌子，方向换了好几次       同一次动作的内部往返
                                → 一段 + 勾「这一段里面有反复」

洗完一个杯子放下，拿起下一个     放下是完成，拿起是重新开始
                                → 切开，右边选同一个事件（A → A）
```

**不要自由选择。** 判不出中间有没有完成证据时标「不确定」，
既不要默认合并，也不要默认切开。

## 四 等待：持续的等待必须单独切出来（v2.1 改了）

上一轮有 21 秒的「等同事装完」被并进了前一个交互节点，于是「等待」这个类型一次都没被用到。

| 情况 | 怎么记 |
|---|---|
| 交互内部的**短暂停顿**（换个手、看一眼、调整姿势） | 留在这个交互节点里，不切段 |
| **持续、能看出起止的独立等待**（等别人做完、等设备、等叫号） | **必须单独切成 特殊状态 / 等待**，不许并进前后的交互节点 |

判据：这段时间里**佩戴者没有对任何物体施加动作**，而且这个状态有明确的开始和结束。

## 五 任务

任务簇 = 共享一个**直接任务目标**的节点集合。允许只有一个节点。
优先用看得见的上下文判归属：同一个工件、同一台设备、同一个工位、同一批物料。

**不要用「出现了环」判定同任务。**

```
A 装配 → [等待同事] → C 记录信息 → D 继续装配
↑                                  ↑
任务 T1                            任务 T1

直接边   A → C       不成立    中间隔着特殊状态
直接边   C → D       成立
任务回访 T1          成立      T1 离开后又出现了
```

**特殊状态会切断边，但不会切断任务回访。** 这是最容易记反的一条。

```
炒菜 → 扫地 → 炒菜
```
是回到了原来的任务，**不表示**炒菜和扫地是同一个任务。

---

## 六 三个必须分开的概念

```
A → B → C → A            同一任务内的流程重复
Task1 → Task2 → Task1     任务回访
                          同一任务的一次具体执行
```

- 节点回访 ≠ 同一个 episode
- 自环 ≠ 新 episode
- 多节点环 ≠ 同一个任务
- 属于同一个簇 ≠ 当前是同一次执行

## 七 提交前会拦你的地方（v2.1 加严）

```
1. 每段都判了类型
2. 特殊状态填了具体哪一种
3. 不确定写了说明：看到了什么、缺了什么
4. 用到的事件都填了：物体、看到的动作、看到的结果、证据第几秒
5. 用到的事件都归了任务，任务都写了归属依据
6. 【新】没有没被任何段用到的事件 —— 删掉
7. 【新】没有零成员的任务 —— 删掉
8. 从头到尾看完
```

「推测的目的」可以空着，不拦你。

---

## 八 这份手册的边界

- 判例全部来自**单一标注者**的旧版本标注，未经人际一致性验证。
- **跨任务切换与任务回访的判例只来自一个批次**，另一批一条都没有，两批的转移速度相差三倍。
- **运输复合状态拆到多细没有规定。** 「走过去 + 取到 + 搬回来」可以是一个状态，也可以拆开。
  照你自己的判断标，在补充说明里写清你是怎么想的——这正是要暴露的东西，不是要你猜标准答案。
