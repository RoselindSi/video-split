# R1：手级 gold 的标注合同（2026-10-12）

配 `src/semhand/hand_level_metrics.py`（指标与 schema）与
`src/semhand/hand_gold_page.py`（标注页生成器）。

**这份 gold 要回答的问题只有一个：每一只自己的手，是不是被一条连续的轨迹
追住了。** 现有的全部 gold 都键在 `rec:tid` 上，也就是跟踪器的输出上，
所以它们问不了这个问题 —— 一只手被切成五段，在那些 gold 里是五行、各自判对错。

---

## §1 标注方式：按固定步长抽帧，逐帧指认两只手

不要求标区间，也不要求画 80 个框。**页面每隔 K 帧（默认 10）停一次，
对这一帧问两个问题：**

```
A 在哪？   → 点画面上的某个候选框 / 自己画一个 / 点「不在画面」
B 在哪？   → 同上
```

一条 400 帧的录像约 40 个抽样帧 × 2 只手 = 约 80 次指认，**绝大多数是一次点击**。

**区间与 anchor 都是导出时算出来的**：可见区间 = 连续若干个抽样帧都「在画面」
的那些段；anchor = 所有被指认的框。所以 anchor 密度等于步长，**按构造成立**，
不靠标注者自觉。

**指标只在抽样帧上计算**（`--at-anchors-only`）。这样 gold 就是实际标过的东西，
没有插值、没有边界误差，也不存在「anchor 太稀导致碎片不可见」——
每一个 gold 帧都是 anchor 帧。

**已知且有界的盲区**：短于 K 帧的碎片可能一个抽样帧都不占，因此不可见。
R0 量到 <10 帧的 own 轨迹占 own 帧的 **0.7%**，所以 K=10 时盲区上界就是这个数。
页面会把实际盲区数报出来。

---

## §2 候选框是无标签的，这一条不可妥协

页面显示的候选框**来自流水线的检测**，但**不带 tid、不带 own、不带 side、
不带任何分组**。

**理由**：这份 gold 要测的正是「这两段是不是同一只手」。
如果页面把流水线的 tid 画出来（同色、同号），标注者会跟着它的分组走，
而那就是在用被考者的答案判卷。所以候选框全是同一种样式、无编号。

**检测器漏检时必须能自己画框**。否则 gold 会被流水线的召回上界卡住 ——
检测器没看见的手就不存在，而那正是我们要测的缺陷之一
（别人的手召回 43.6% 是已知的，自己的手虽然 96.0% 但小框一带仍有漏）。
页面的「自己画」路径就是为此留的，而且导出时会标出哪些 anchor 是手画的。

---

## §3 两条判断规则，标注者要做的就是这两件事

### 规则一：`A` / `B` 在整条录像内恒定

**手出画又回来，仍然是原来那个 key。** 这一条正是在测跨遮挡的身份保持，
所以它是**标注者要做的判断**，工具补不了。

`A` 和 `B` 是匿名的 —— **不要求你判断哪只是左手**。你只需要在这条录像里
把两只手区分开并一直跟住。如果你看出来了，可以在 `side_note` 里写一句，
它不参与计分。

> 为什么不标左右：`side` 的多数票可靠性约 0.88（单个碎片内部 4.4% 的帧
> 与自身多数票不一致、55.6% 的碎片至少翻转一次）。如果 gold 必须说左右，
> 指标就继承这个 0.88，从而分不开「手丢了」和「手认错了」。

### 规则二：「在画面」的判据

```
在画面 = 手的任何部分在画面内，且你能辨认出它是手
        遮挡但仍可辨认 → 算在画面
        完全出画 / 糊到认不出是手 → 不在画面
```

**拿不准就点「不确定」**，不要猜。不确定的抽样帧**从分母里剔除**，
而它的数量就是结论的边界 —— 不确定越多，能说的越少。
（这是 `against_gold` 里已经立过的口径：`not_hand` 与 `uncertain` 不能并成
一个「已排除」，因为前者是检测器的问题、后者是题目本身没有答案。）

## §4 四个会反复遇到的情形，答案先写下来

| 情形 | 怎么标 |
|---|---|
| 两只手叠在一起、只能看出一只 | 看得见的那只照常指认；另一只点**不确定**，不要猜 |
| 画面里有别人的手 | **不指认**。A/B 只能是佩戴者自己的手；别人的手留着不管 |
| 候选框把两只手框进了一个 | 自己画两个框；导出会记下这是手画的 |
| 同一只手有两个重叠候选框 | 挑贴合更好的那个。两个都不好就自己画 |

**「别人的手不指认」会让它们在指标里成为「分配不到任何一只手的轨迹」**，
也就是污染项。那是对的：在不打码的前提下，别人的手混进 owner 集合是污染，
不是隐私失效。

## §5 规模与试标

**先在 3-5 条录像上试标**，判据是**两个标注者对规则一能否对齐**：

```
同一条录像两人独立标 → 比较「A 的可见抽样帧集合」与「B 的」
允许整体 A/B 互换（匿名），所以比较时取两种对应里一致率高的那个
一致率 >= 0.9   → 合同可用，扩到 20-30 条
一致率 < 0.9    → 规则一在实践中不可判定，这时要改的是指标而不是标注者：
                  退到读法 B（只要 owner 框集合完整干净，不要求身份保持）
```

**这一步不能跳。** 读法 A 的全部价值建立在「同一只手」这个判断可靠之上，
而那是个经验问题不是定义问题。如果人都对不齐，指标就没有可测的对象。

试标选片**不得用模型分**（这个项目的选片 proxy 曾经被证明是反向的，r = −0.46）。
从 `e2e_v4` 那 10 条里按录像名排序取前 5 条。

## §6 导出格式

页面导出 `hand_gold_v1`（`hand_level_metrics.py --schema` 可打印）：

```json
{
  "schema_version": "hand_gold_v1",
  "recording": "R26_0824_121025",
  "stride": 10,
  "annotator": "r1",
  "hands": [
    {"hand_key": "A", "side_note": "", "intervals": [[400, 480]],
     "anchors": [{"frame": 400, "box": [908,1078,1122,1290], "drawn": false}]},
    {"hand_key": "B", "intervals": [], "anchors": []}
  ],
  "uncertain": [{"frame": 430, "hand_key": "B"}],
  "sampled_frames": [400, 410, 420, 430]
}
```

`sampled_frames` 必须带，因为指标只在它上面算 ——
没有它就分不清「这一帧手不在」和「这一帧没标」。
