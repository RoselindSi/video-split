# 一、手部线（这条是主线）

## 目标（2026-10-15 重新定义）

**不再打码。** 流水线已经数周不产出马赛克，人脸检测器也在 `ac61366`（10-10）关掉了。
所以**隐私泄露不再是这条线的优化目标或错误成本**。

要检测的问题是：**错框被 `track_join` 接入目标手轨迹，造成身份或轨迹污染**，
按它对**机械臂训练数据**的影响判断严重程度。

| 项目 | 定义 |
|---|---|
| `other_hand` | 保留为错误来源标签，不再带「隐私灾难」成本 |
| `not_hand` / 自己前臂 | 同样按错误接入及其训练影响评估 |
| 别人的手出现但很远 | **不能仅凭出现就判录像有问题** |
| `n_faces` | 从筛选规则中移除 |

取消的是**隐私优先级**，不是证明所有错框危害相同：别人的手可能导致身份切换，
前臂框可能造成定位偏移，严重程度取决于污染时长、轨迹是否被替换、以及如何进入训练。
当前统一统计「非目标框错误接入」，保留来源标签。

**指标分层**：
- **主指标**：实际被接入的非目标框比例；受污染的目标轨迹比例。
- **辅助指标**：满足距离条件的候选数，**只用于筛选值得复核的录像**。
- **错误类型**：分开保留，不预设成本权重。

## 已经定死的东西

- **`track_join` 窗口 = 5.0 秒 = 150 帧**（`src/rig/track_join.py`）。
  旧值 30 帧的注释写着「6fps 下 5 秒」，而源是 30fps/stride 1 —— 换算错了 5 倍。
  改成按秒写。50–150 的置信区间完全重叠，手级 gold **分不出谁更好**，
  所以取值是按换算定的，不是从曲线上挑的。
- **窗口不是瓶颈**：留出集上改窗口只赢 1/19 处。近七成的手不由单一轨迹持有，
  两只手中位切成 5 条轨迹、42% 有洞。瓶颈是碎片化。
- **`forced_pairs` 的真实判据是四条**（不是只有距离）：
  `gap<=0` 硬否 → `gap<=150` → a 末框中心到 b 首框中心 `<= 3.0×width(a末框)` → **候选恰好一个**否则弃权。
- **一次已有的主指标测量**（`ac61366`）：对 291 条人工标注轨迹，
  **部署顺序下从未把佩戴者的手和别人的手并在一起**；
  但跑在**未经 hand-ness 过滤**的轨迹上会错并一次、混入非手十五次。
  所以 stage 3b 放在过滤之后是测量结果，不是偏好。
