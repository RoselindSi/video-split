# 手部线：两个瓶颈的计划，以及它要达到什么程度才算有力材料（2026-10-12）

## §0 先推翻我自己给的那个排序

上一轮我说「tracker（碎片化）> 检测器小框召回」。读完 `src/rig/track_join.py`
的实测之后，**这两件事不是独立的，而且剩下的 tracker 工作主要就是检测器工作。**

`track_join` 已经上线（`ac61366`），在 52 条录像上实测：

```
两只手到达时是中位 5 条轨迹，42% 的轨迹有空洞
碎片端的续接候选分布：  无候选 57.9%   恰好一个 31.8%   多个 10.3%
把 31.8% 那批全接上：   碎片 321 -> 219
```

**31.8% 已经收掉了。** 剩下的两块性质完全不同：

- **10.3% 有多个候选** —— 真的歧义，挑最近的是「把猜测打扮成几何」。这一块小。
- **57.9% 根本没有候选** —— 这才是大头。而「没有候选」意味着在那个时间窗里
  **检测器没有产出可接的框**。

所以：**碎片化的残余主要是检测缺口的表现，不是关联算法的缺陷。**
先修检测器召回，碎片化会跟着降；反过来不成立。

顺带，`track_join` 已经附带回答了一个会被问到的问题：21.6% 的接合左右手多数票
不一致，看着像五分之一接错了 —— 但单个碎片内部已经有 4.4% 的帧与自己的多数票
不一致、55.6% 的碎片至少翻转一次，隐含的多数票可靠性约 0.88，**21.6% 单靠这个
就能解释完**。所以 `side` 不作为闸门，而是在合并后重算。

## §1 这条线现在的真实位置

**工程部分成立：** 五个 stage 跑通，184 秒/录像（从 409 降下来），两种交付模式，
无马赛克残留，README 写明口径与缺陷。

**判别部分不成立：** 202 条盲标 gold（75 OWNER / 127 OTHER，**来自仅 10 条录像**）

| | OWNER 整轨放行 ← 主指标 | OWNER 误糊 | 别人的手被放行 |
|---|---|---|---|
| 带描述 | **49.3%** | 50.7% | 24.4% |
| 不带描述 | 37.3% | 62.7% | 15.0% |

**一半的 OWNER 轨迹被误糊**，所以人工复核跑不掉，这条线目前不是一个
「可自动化」的系统。

**作为申请材料，现在的问题不是数字不好看，是没有一个可防守的数字。**
10 条录像、而录像才是样本单位。任何「我把 X 提到 Y」的说法在面试里第一个问题
就是「n 是多少、怎么聚类」，而现在的答案是 10。

## §2 Phase A：先做归因，不做修复（最便宜，1-2 天）

**不要先动 tracker 或检测器。** 先回答一个问题：

> 那 50.7% 的 OWNER 误糊里，有多少是**碎片化造成的**？

已有的事实只给了方向而不是份额：误糊集中在短碎片（<10 帧 7.6%、≥34 帧 0.7%），
但那是**碎片级**的比率，不是**误糊总量**的归因。短碎片比率高，可是如果短碎片
只占少数帧，修好它也动不了主指标。

**要测的：** 对 202 条 gold 轨迹，按「它在 stage 3 输出里被切成几片」和
「最长片占全轨多少帧」分组，报每组的 OWNER 放行率。

**判据（事前定）：**

```
碎片数 >= 3 的那些 gold 轨迹，若其放行率显著低于碎片数 1 的 → 修 tracker 有意义
两组放行率差的 CI 跨零                                  → tracker 不是主因，
                                                          Phase B 取消，直接跳 §4
```

**聚类单位是录像不是轨迹**，bootstrap 按录像重抽 —— 这条在这个项目里已经吃过
三次亏（pooled 是录像间捷径）。

**工具缺口：** `ownergate/against_gold.py` 目前不按轨迹长度/碎片数分解。
要加一个 `--by-fragments`，拿 stage 3 的 `_tid_map.json` 和 gold 对齐。

## §3 Phase B：检测器召回，而不是关联算法（Phase A 过了才做）

**不做的事（已经测过，别重做）：** 提分辨率。1024/1536/1920 在 0.60 门槛下
全是 44.3/44.2/44.1%，而自己的手反而从 85.5 掉到 75.7。**分辨率不是瓶颈。**

**真正的杠杆是门槛，不是模型。** 别人的手原始召回 70.5%，过了 0.60 的新建门槛
只剩 43.6% —— **26.9 个点丢在阈值上，不是丢在检测上。**

但这里有一个已经测到的反向约束，不能无视：出生阈值不对称
（新轨迹 0.50 进 OWNER，而已存在的 OTHER 要 0.70），9 条候选全量人工判 **7/9 错**，
改成 0.70 是 **114 帧 : 4 帧** 的交换。**降门槛会直接伤 OWNER 稳定性。**

所以 Phase B 的形状不是「降门槛」，而是：

**B1（最小动作）：低置信度框只用于「续接」，不用于「新建」。**
一个碎片端在窗口内找不到候选时，把门槛从 0.60 临时降到 0.35 **只在那个
时空窗口里**找续接 —— 已有轨迹的身份不是从这一帧推断的，所以这里用低分框
不引入新的身份判断。这正好对上 §0 那 57.9%。

**事前判据：**
```
碎片数下降 且 OWNER 放行率 CI 不跨零向上 且 别人的手被放行率不恶化  → 采纳
OWNER 放行率改善但护栏恶化                                      → 报成取舍，不默认采纳
碎片数降了而放行率不动                                           → 说明碎片化不是主因，
                                                                 回到 Phase A 的结论重读
```

**B2（只在 B1 不够时做）：小框专用检测头。** 别人的手中位 87px，而
`small-boxes-hold-half-the-nonhands` 测到 <150px 的框里非手率 12.2%
对 >=150px 的 5.9%。所以小框上同时是「召回低」和「精确度低」，
单纯召回提升会把非手一起带进来。**B2 之前必须先有小框上的 hand-ness
可用**，而 `handness-collapses-on-small-boxes` 说 23-28px 上判非手只有 5.5%
且无阈值可救，30-100px **从未测过**。

→ **B2 的前置条件是一次测量，不是一次训练**：在 30-100px 这一带测 hand-ness。
这一带正是别人的手的中位（87px）所在。

## §4 Phase C：那个从没跑过的冻结验证（决定材料能不能用）

`ownergate/FROZEN_VALIDATION.md` 里已经写好了：**20-30 条全新录像、三条臂
（G0 不接语义门 / G1 带描述 / G2 不带描述）、逐轨迹配对、按录像聚类**。
判据已冻结，**从没执行**。

**这一条是材料的闸门，不是锦上添花。** 没有它，主指标是 10 条录像上的 49.3%；
有了它，才有一个能回答「n 是多少」的数字。而且它和 Phase A/B 的顺序是可以交换的
—— 它甚至应该**先跑一半**：先在新录像上复现 49.3%，确认 10 条那批不是运气。

**成本是标注，不是算力。** 20-30 条录像的轨迹级盲标。

## §5 怎样才算有力的申请材料

**现在的叙述是弱的：** 「我搭了一条第一视角手部隐私流水线，184 秒一条录像。」
这是工程量的陈述，面试里问三个问题就会落到「所以它准不准」，
而答案是一半。

**可以做到的强叙述，有三个层次，由上面的 phase 决定能讲到哪一层：**

### 层次 1（已经成立，现在就能写）——「我证明了瓶颈不在大家以为的地方」

这是这条线目前**最有价值**的东西，而且不需要再做任何实验：

- 一整条线在改分类器：蒸馏学生、语义层、换骨干、负例扩充。
- 而测量说瓶颈不在那里：**误糊集中在短碎片**（<10 帧 8% 判错 / ≥34 帧 0%）；
  **学生与老师不可区分**（ΔAUC 与 Δ零误糊两个 CI 都跨零）；
  **提分辨率不改善召回**（44.3/44.2/44.1%）；
  **负例在 ~1400 饱和**（895→1388 涨 0.036，1388→2373 涨 0.000）。
- 四个独立的否定结果指向同一个结论：**这是关联与检测的问题，不是分类的问题。**

**这个层次的说服力来自方法而不是结果**，而方法是可以展示的：冻结判据、
预注册、以及一串被自己推翻的结论（「老师 0.980」是覆盖偏差、
「暴露率 0.57%」的分母是错的、「封顶」被一行代码关掉了半年）。
**会看 git log 的人，这比一个漂亮的数字更可信。**

### 层次 2（Phase A + B1，约 1-2 周）——「我据此修好了它」

需要的是一个**主指标上的、CI 不跨零的、按录像聚类的**改善。
B1 是成本最低的候选，而且它的机制可以用一句话讲清楚：
**低置信度的框足以续接一条已经确立身份的轨迹，却不足以新建一条。**

这句话本身是个有意思的设计判断，面试里经得起追问。

### 层次 3（Phase C，加上标注成本）——「而且这个数字立得住」

20-30 条全新录像上三条臂配对。有了它，层次 2 的数字才能被引用；
没有它，层次 2 只是 10 条录像上的一个点。

---

## §6 顺序与止损

```
A  归因（1-2 天，纯分析）          判据不过 → B 取消，只写层次 1
B1 低分框只用于续接（3-5 天）       判据不过 → 不做 B2，只写层次 1 + A 的归因
B2 小框 hand-ness 测量（先测不训）   30-100px 不可用 → 小框这条路关闭
C  冻结验证（标注成本主导）         与 A/B 可并行，而且应该先跑一半验 49.3%
```

**不做的事，写下来免得回头又做：** 提分辨率、继续扩 handness 负例、
换骨干、把 vLLM 调到贴近本地基线、在 `side` 上加闸门。
这五件都已经有否定的实测。

---

## §7 一句话

**最有力的材料不是「我做出了一条 work 的流水线」，而是
「我花了半年证明大家（包括我自己）在改错的东西，并且给出了证据」** ——
前者现在不成立，后者已经成立。Phase A/B/C 是把后者升级成
「并且我据此修好了它，而且这个数字在 20-30 条新录像上立得住」。
