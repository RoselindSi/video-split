# B2 第三轮结果：细化粒度不能绕过这个限制（2026-10-12）

第三轮换任务族（修车）+ 动作级粒度 + 强制 id 复用，标了 30 条中的 **10 条**后停止。
停止不是因为疲劳，是因为这 10 条已经把问题回答了，而且回答得比产出率更深。

数据 `results/auditor/b2_egoexo/b2_bike_export_r1_partial.json`（10 条 final，
其余 20 条为空草稿），分析 `src/auditor/boundary/b2_grain_fold.py`，
产物 `results/auditor/b2_egoexo/b2_bike_fold_r1.json`。

## 一、细标确实把 branching 做出来了

```
Ego-Exo4D keystep 粒度（同一族 30 窗口）    G-branch 0.00 /窗口
人工动作级 + 强制 id 复用（10 窗口）        G-branch 0.50 /窗口
```

0.50 正好落在冻结判据的宽端（≥0.5 每录像）。单看这一行，粒度假设成立。

## 二、但 5 个分叉的前驱全是同一个节点

```
拿工具 -> 给轮圈充气          拿工具 -> 取下轮圈
拿工具 -> 检查轮圈            拿工具 -> 拿一个新的轮圈充气
拿工具 -> 给装好的轮圈充气

前驱分布 {拿工具: 5}    占比 5/5 = 100%
```

标注者自己写的 branch condition 就是证据，全部是工具身份：
「这次拿的是充气枪」「这次拿的是刻刀」「这次拿的是螺丝刀」「因为拿的是钳子」。
**条件是手上拿着什么，不是任何需要判断的状态。** 拿起充气枪之后去充气，
不是一个决策点，是同一个动作的开头。

这正是本项目当初否掉 EPIC-KITCHENS 的那个东西。
`egoexo_topology_prescreen.py` 的 docstring（写于数据到达之前）：

> EPIC 60.2% 的表面分叉落在 `pick-up` 和 `put-down` 上，因为一个叫「拿起」的
> 节点后面可以跟任何东西，**它的高出度来自构造而不是来自决策**。

区别只在于：那次是数据集的标注体系造的，这次是我们自己的细化造的。

## 三、折叠掉取得类状态之后归零

规则：**状态 = 作用于什么 + 怎么作用。只为取得手段而存在的移动不是状态，
并入它服务的那个动作。**

分界不在动词而在是否有作用于工件的动作，所以 `拿充气枪` 折叠，而
`拿充气枪给轮胎充气`、`拿一个新的轮圈充气` 保留；**取得零件也不折叠**
——换胎而不是补胎是个决策。10 条里 28 个代号的逐条分类见
`b2_bike_fold_r1.json` 的 `code_classification`，可以逐项反驳。

```
① 按标注原样              决策 55   |S|>=2  5   G-branch 5（0.50/窗口）
② + 同名代号合并           决策 54   |S|>=2  5   G-branch 5（0.50/窗口）
③ + 「?」阻断相邻合并       决策 55   |S|>=2  5   G-branch 5（0.50/窗口）
④ + 去掉纯取得工具状态      决策 33   |S|>=2  0   G-branch 0（0.00/窗口）
```

**0.50 全部来自「拿工具」一个节点，折叠后归零。** ② 和 ③ 是两处标注瑕疵的修正
（见第六节），对结论零影响；变的只有 ④。

## 四、真正的限制是一个访问次数，它比产出率更有价值

`G-branch` 要求 `|S| >= 2`，即前驱**在此之前已被离开两次**，
所以必须有某个状态被访问 **3 次以上**。一个状态访问两次只能给出 `|S| = 1`。

| | 访问最多的真实状态 | 次数 | 取得类最多 | 次数 |
|---|---|---|---|---|
| cmu_bike02_3_w000129 | 拿充气枪给轮胎充气 | 1 | 拿充气枪 | 1 |
| cmu_bike05_4_w000008 | 给轮胎充气 | 2 | 拿起工具 | 2 |
| cmu_bike11_2_w000001 | 拧紧车轮上的零件 | 2 | 无 | 0 |
| cmu_bike18_3_w000001 | 把辐条固定好 | 1 | 拿工具 | 1 |
| cmu_bike19_3_w000001 | 把充气阀门拧上 | 1 | 拿工具 | 2 |
| cmu_bike20_3_w000001 | 把充气阀门拧下 | 1 | 拿工具 | **3** |
| fair_bike_01_15_w000005 | 取下轮圈 | 2 | 拿工具 | **3** |
| fair_bike_01_3_w000003 | 取下轮圈 | 1 | 拿工具 | **3** |
| fair_bike_01_7_w000000 | 拿一个新的轮圈充气 | 2 | 拿工具 | **4** |
| fair_bike_02_11_w000167 | 装轮圈 | 1 | 拿工具 | 1 |

```
真实状态最大访问次数     1 次 6 条 / 2 次 4 条 / >=3 次 0 条
取得类最大访问次数       >=3 次 4 条（最多 4 次）
```

**真实状态一条都没到 3 次；唯一反复被经过的东西是「手上拿着工具」。**
这是任务形态决定的，不是标注决定的：修车是单向流程，人会反复回到工具堆，
但不会反复回到「检查轮圈」。

这一条写成判据比写成产出率有用：**要让 `|S| >= 2` 由真实状态产生，
任务必须让同一个真实状态在一条录像内出现 3 次以上，并且每次之后去不同的地方。**
它直接说明了重标需要产生什么，而产出率不说明。

## 五、为什么再细一点也没用

把 `拿工具` 拆成「伸手 / 握住 / 抬起」，访问次数再翻倍，G-branch 跟着涨。
**这是一个可以靠把过渡动作切得更碎无限刷高的指标。** 上限是任意的，
所以它不能作为「域里有 branching」的证据。

反过来说：**第一轮厨房的 hub 是真实的，这里的不是。** 厨房那三条有 revisit 的
录像，hub 是「照看锅」——一个可以停在里面、观察、然后决定去拿盐还是装盘的状态；
修车这里的 hub 是「手上拿着东西」，一个过渡。两者的区别恰好就是第三节那条规则。

## 六、两处标注问题，已修，不影响结论

- **`cmu_bike20_3`：代号 `E` 和 `F` 同名「拆轮圈」。** id 复用失败——同一个状态
  拿了两个号，凭空多出一次 `E→F` 转移。正是本轮新规则要防的事。合并后决策 55→54，
  G-branch 不变。
- **`cmu_bike11_2`：`A, ?, A, B`，「?」夹在两个 `A` 之间。** `b2_yield.chain()`
  跳过 `?` 后做相邻去重，于是这次 revisit 被**静默合并**掉。第一轮厨房逐条确认过
  没有这种情况，本轮出现了。

第二条是真实的口径漏洞：**看不清的片段会吃掉一次复现。** 但修复不进冻结的
`chain()`——那套阈值 2026-09-28 冻结，评估器不能动。所以
`b2_grain_fold.py` 提供 `--qmark-breaks` 作为另一种约定并两边都报；
本批上它改变不了任何数字，这是结论可以忽略它的唯一理由。

## 七、结论与停止

**第三轮不改变 B2 的 NO-GO，而且把它的理由从「这一族没有」收紧到
「细化粒度不能制造它」。**

三条数据线（内部池 / EPIC / Ego-Exo4D）加上这一轮的粒度实验，
**第四次**指向 spec 判据一那句话：

> 录像必须让同一种可观察状态在同一条录像内重复出现，并且根据当时的条件
> 进入不同的后续状态。

而「重复出现」在实践中的硬门槛是 **3 次**，不是 2 次。

**剩下 20 条不标。** 按第三节的规则重标，前 10 条的状态表也要改，
而再标 20 条只会继续累积同一种伪分叉。抗原那批（`egoexo_b2_antigen`）同样封存。

对 `docs/paper_skeleton.md` 的影响：这 10 条是 Contribution 1 最干净的一组证据
——它不是「我们没找到 branching」，而是**「把粒度细化到可以制造 branching 的程度时，
制造出来的是 transport primitive，而真实状态的复现次数不随粒度增加」**。
这比单纯的稀缺性陈述更难反驳，因为稀缺性的标准反驳就是「标细一点」。
