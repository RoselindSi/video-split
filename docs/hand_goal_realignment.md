# 目标归位：自己的手的稳定追踪（2026-10-12）

目标重申为**自己的手的稳定追踪**之后，上一轮的 W1b/W1c 计划有一处根本性的错位
要先纠正。这份文件取代 `docs/hand_line_plan_work.md` 与
`docs/hand_gate_w1b_plan.md` 的**目标与指标**，保留它们的测量结果与基础设施记录。

---

## §1 现有指标没有一个在测这个目标

交付件是 `(tid, 帧区间, 整轨 own/side/is_hand) + 逐帧框`。
在「稳定追踪自己的手」这个目标下，合格的产出是：

> **每一只自己的手，被恰好一个 tid 连续覆盖，且该 tid 判为 `own=1`。**

而现有的全部 gold 的 key 是 **`rec:tid`** —— 键在**跟踪器的输出**上。

**所以一只手被切成 5 个 tid，在 gold 里就是 5 行、各自独立判对错。
「有没有做到一只手一条轨迹」用这份 gold 从构造上就测不出来** ——
gold 的单位正是碎片化所破坏的那个东西。

两个具体后果：

- **`96.6%` 的轨迹级归属准确率与这个目标基本无关。** 它说的是「给定跟踪器切出来的
  这一段，判对了谁的手」。一只手切成 5 段、5 段全判对，这个数是 100%，
  而追踪是失败的。
- **`49.3% 整轨免打码放行率` 是打码时代的指标。** README 自己写着
  「视频里没有任何马赛克，这是查过的」，而 `against_gold` 的主指标仍然叫
  「整轨免打码」、还带一条隐私护栏。**不打码，就没有隐私护栏。**

## §2 三个量的含义随目标改变

| | 打码目标下 | 稳定追踪目标下 |
|---|---|---|
| 碎片化（2 只手 → 中位 5 条 tid） | 次要原因 | **主要缺陷本身** |
| 别人的手被放行 | 隐私失效 | **污染** owner 轨迹集，成本由下游定，不是隐私 |
| `unsure` 弃权（45%） | 被打码 | 没有可用标签 = 轨迹集里一个洞 |
| `没跑到`（12%） | 被打码 | **最坏情形：这只手根本没有轨迹** |

**「别人的手被放行」从一条不可逾越的护栏，降级为一个由使用方设定的污染预算。**
这直接改掉 W1c 的判据 —— 我当时按「护栏 ≤0%」去找操作点，而在不打码的前提下
零污染不是一个有特权的点。

## §3 能测这个目标的指标

**单位必须是「手」，不是「轨迹」。** 对每一只自己的手（在一条录像里的一个实例）：

```
n_tids      覆盖它的 tid 数                      理想 1
coverage    它可见的帧里被 own=1 的 tid 覆盖的比例   理想 1.0
purity      被覆盖的帧里覆盖者判为 own=1 的比例      理想 1.0
switches    沿着这只手发生的 tid 切换次数            理想 0
```

**主指标一句话：**

> **自己的手里，有多大比例被单一的 `own=1` 轨迹覆盖了其可见帧的 ≥X%。**

这需要**手级 gold**：标注者在采样的录像里标出每只自己的手的可见区间，
然后拿流水线输出去算覆盖。**这是一份新的标注合同**，但它是唯一能测到
所述目标的东西。现有的 `own_gold_p*`、`gold_b*`、`fresh_gold_p*` 都是 tid 级，
无法改造 —— 它们记的是「这一段是谁的」，不是「这只手在哪些帧里」。

## §4 现在就能做、零标注的代理指标

**owner tid 数 对 手数。** 一条录像里佩戴者有两只手；如果输出里有 9 个
`own=1` 的 tid，碎片化就是可见的，**不需要任何标注**。

```
每条录像：own=1 的 tid 数、它们的帧区间、区间之间有没有时间重叠
          （重叠 = 同时存在两条以上自己的手的轨迹 → 其中至少一条是错的或重复的）
理想：2 条互不重叠、合计覆盖手可见的时段
```

这个量可以直接从交付的 `decisions/<rec>.decisions.csv` 算，**今天就能跑**，
而且它正是 `cap-coupling-was-off` 那条记忆测到过的东西 ——
「16.5% 的帧判出 >2 只自己的手」。那时它被当成封顶 bug 的症状，
**在新目标下它就是主指标的一个直接分量。**

**它测不到的**：一只手被切成两段但两段不重叠时，这个代理看不出来
（它只能数 tid 和查重叠，不知道两段是不是同一只手）。所以它是必要不充分，
手级 gold 仍然要做。

## §5 计划重排

```
R0  零标注代理普查        从 decisions csv 算 own=1 tid 数 / 重叠 / 时段覆盖   ← 立刻可做
R1  手级 gold 合同        定义「一只手的一个实例」与可见区间的标注规则；
                          先在 3-5 条录像上试标，确认标注者之间能对齐
R2  手级指标实现          coverage / purity / n_tids / switches
R3  按 R0+R2 的结果定方向  碎片化是主缺陷 → track_join 的残余（57.9% 无候选端）
                          与检测缺口；而不是继续调 gate 的阈值
```

**W1b 不取消但改判据。** 补视角解决的是 `unsure`，而在新目标下 `unsure`
意味着「这条轨迹没有可用的 own 标签」—— 它仍然是损失，但判据不再是
「零泄漏下放行率」，而是**「它能把多少条 own=1 的轨迹补全成连续覆盖」**。
所以 W1b 要等 R2 的指标就位之后再跑，否则跑完也不知道算不算赢。

**W1c 的结论仍然成立但降级**：它证明了「换阈值救不回弃权，因为 1-2 视角的
分数没信息」，这个机制结论不依赖目标。只是它的那张「护栏 vs 可用性」曲线
在不打码的前提下不再是决策依据。

## §6 一处需要你定的歧义

「稳定追踪自己的手」有两种读法，工作量差别很大：

**读法 A：逐手身份保持。** 每只手一条轨迹，左右手不混，跨遮挡后接回同一个 id。
→ `side` 成为一等问题，而它现在不行：`track_join` 测到单个碎片内部已有 4.4%
的帧与自己的多数票不一致、55.6% 的碎片至少翻转一次，隐含多数票可靠性约 **0.88**。
A 读法下这 0.88 是主指标的上限之一。

**读法 B：owner 框集合完整且干净。** 不要求区分左右、不要求跨遮挡接回同一个 id，
只要求「所有属于自己的手的框都被收进来、别人的手别混进来」。
→ `side` 无关，碎片化只在它造成漏检或污染时才算缺陷。

**我按 A 写了上面的计划**，因为「稳定追踪」在字面上含有跨时间的身份保持。
如果你要的是 B，那么 R1 的标注合同会简单得多（不标手实例、只标 owner 框），
而 `side` 整条线可以不管。

**在你定之前，R0 两种读法都需要**，所以可以先做。
