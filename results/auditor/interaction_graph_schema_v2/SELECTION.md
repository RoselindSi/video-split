# E0 表示验证：结构普查与样本选择依据

生成于 2026-09-24，对应实验计划 §9.1 / §10.1 P0。
工具：`src/auditor/boundary/interaction_graph_structure_census.py`
数据：`results/auditor/interaction_graph_release_v1/frozen_annotations/`（60 条，单标注者冻结版）

本文件只做两件事：把六个结构在 60 条开发视频里的分布数出来，并据此定下 E0 的样本。
**它不是 v2 的测量结果**，也不能和 §3 里 v1 口径的 161 / 171 / 9 混用——那些数字属于 v1 合同，
改动 self-loop 与 Task Cluster 语义之后必须另行转换与审计。

## 判定规则（先写死，再统计）

| 结构 | 判定 |
|---|---|
| 持续重复 | 某一段 `repeats_within_segment == true` |
| 同节点再次出现 A→A | 去掉特殊状态后，相邻两次出现是同一节点 |
| 线性多步骤 | 同一个 procedure group 在本视频里出现 ≥3 个不同节点 |
| 多步骤循环 | 同一 group 内，某节点在**至少隔了一个不同节点**之后再次出现 |
| 跨任务切换 | 相邻转移的两端 group 不同（两端都必须有 group） |
| 离开后返回 | 把连续同组压成一段之后，group 序列里出现重复 |

三条约束，直接来自合同：

- **特殊状态不作为端点。** `未开始` / `idle` / 遮挡是带时间的状态，§8.3④ 禁止跨其间隔合成直接边。
  所以相邻对只有两端都不是特殊状态时才算一次转移；跨越特殊间隔的复现单独记 `across_special_gap`，
  既不静默计入也不静默丢弃。
- **A→A 是「状态复现」不是「实例重置」。** §8.3① 明确自环只表示状态回来了。字段按观测命名。
  是否是新实例需要 completion / reset 证据，v1 标注不携带，补上它正是 E0 的任务。
- **任务回访是 group 级，且不由多步循环蕴含。** §8.3③ 说拓扑循环不能单独判定任务连续，
  所以 `A→B→A`（簇内）和 `T1→T2→T1`（簇间）分开计，永不相加。

## 样本：8 条

贪心最小覆盖只要 2 条就能勾完六个格子，**但那是陷阱**——每个稀有结构只有一个实例，
据一个实例写合同就是写轶事。所以目标改成：稀有结构取尽（现存全部），其余四个结构各 ≥3 条实例。

强制 4 条，因为它们是现存**全部**的跨任务证据：

| 录像 | 批 | 段 | 节点 | 覆盖 |
|---|---|---:|---:|---|
| mosaic_graph_0002 | mosaic_complement | 5 | 4 | 持续重复、A→A、线性多步、跨任务、**任务回访** |
| mosaic_graph_0006 | mosaic_complement | 5 | 5 | 持续重复、跨任务 |
| mosaic_graph_0020 | mosaic_complement | 4 | 4 | 持续重复、跨任务、**任务回访** |
| mosaic_graph_0030 | mosaic_complement | 3 | 3 | 跨任务 |

补足其余四个结构各 ≥3 条，批次尽量均衡：

| 录像 | 批 | 段 | 节点 | 覆盖 |
|---|---|---:|---:|---|
| graph_review_0023 | repeated_actions | 11 | 3 | 线性多步、多步循环 |
| graph_review_0002 | repeated_actions | 10 | 4 | 持续重复、线性多步、多步循环 |
| mosaic_graph_0008 | mosaic_complement | 13 | 2 | A→A、多步循环 |
| graph_review_0016 | repeated_actions | 20 | 1 | A→A |

合计：持续重复 4、A→A 3、线性多步 3、多步循环 3、跨任务 4、任务回访 2；批次 5 / 3。

计划要 10–15 条，这里 8 条已满足覆盖判据。**剩余名额应当买深度而不是买格子**：
优先补重复动作批的线性多步与多步循环（用来检验从马赛克补集写下的规则是否在另一批成立），
而不是再加一条已经覆盖过的结构。

## 45 个 procedure group 的成色

| | 个数 |
|---|---:|
| 单节点组 | 16 |
| 只出现在一条视频 | 37 |
| 跨视频复用 | 8 |

v2 允许单节点 Cluster，所以 16 个单节点组本身不违规。但 **37/45 只在一条视频里出现**，
意味着当前的簇词表几乎完全是视频局部的；§8.5 把跨视频模板列为另一项实验，需要开发集学习并报告跨来源划分，
不能默认现有 45 个组构成一个可复用的任务词表。

## E0 必须先裁决的一件事

`mosaic_graph_0020` 的任务回访是：

```
pg_electrical_assembly → pg_collaboration_waiting → pg_work_documentation → pg_electrical_assembly
```

而 `pg_collaboration_waiting` 的定义是「等待另一位操作者完成相关装配步骤」，1 节点 1 视频。

v2 把 Task Cluster 定义为**共享一个直接任务目标的节点集合**。等待同事完成步骤不是一个任务目标，
而 §8.3④ 要求把不可见 / idle 保留为**带时间的特殊状态**。若按 v2 重新归类，
0020 就不再是三簇回访，而是

```
pg_electrical_assembly → [特殊状态] → pg_work_documentation → pg_electrical_assembly
```

且 §8.3④ 禁止跨特殊间隔合成边。

同类问题还有 `pg_person_following`（跟随他人行走，2 节点 2 视频，是 0006 跨任务链的一环）：
它写了目标，但没有物体也没有可见结果，而 v2 的 Node 要求**动作 / 物体 / 可见结果共同支持匹配**。

**所以 v1→v2 的映射不是改名，它能把最稀有那个结构的证据从 2 条变成 1 条。**
这个裁决必须在写 schema_v2 之前做，而且要写进未映射清单。
