# 手级标注页面怎么做

生成器：`src/semhand/hand_gold_page.py`。输出是**单文件 HTML**，帧以 base64 内嵌，
不依赖任何服务器——发给标注者就能直接在浏览器里打开，标完导出 JSON。

```bash
python3 src/semhand/hand_gold_page.py \
    --detect2   <录像>.detect2.csv \
    --recording R26_0825_113022 \
    --embed     frames.json \
    --out       handgold_R26_0825_113022.html
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--detect2` | 必填 | 该录像的 detect2 csv，候选框从这里来 |
| `--recording` | 必填 | 录像名，写进导出的 JSON |
| `--grid-start` / `--grid-end` | 400 / 800 | 抽样网格区间（不含右端） |
| `--stride` | 10 | 步长。400→790 共 40 帧 |
| `--width` / `--height` | 1920 / 1520 | 画面尺寸（cam3 = cam34 左半） |
| `--embed` | — | `{frame: base64_jpeg}` 的 json，内嵌进页面 |
| `--out` | 必填 | 输出 HTML |

---

## 四步，每步各有一个踩过的坑

### 1. 抽样网格：固定起点与步长，**不看有没有检测**

见 `hand_gold_page.py` 的 `sampled()`。两个坑都来自"让数据决定网格"：

- **锚在 `detect2` 首帧上**：十条里八条恰好从 400 开始纯属巧合，
  153159（首帧 415）和 015550（412）直接生成了**零帧**的页面；
  而且 gold 之间能不能合并统计变成了运气。
- **「该帧有检测才取」**：153159 上静默丢掉 37 帧里的 16 帧，
  而丢掉的**恰好是暴露漏检的那些**——用检测结果决定看哪些帧，就看不见检测的失败。

### 2. 抽帧并内嵌

从源视频按网格抽这 40 帧，base64 内嵌。

**坑**：原图 1920×1520 内嵌后页面 8–9 MB，上传会 408 超时（10.9 MB 的反而成功过，
所以不是硬上限，是超时）。现按 **1024px / quality 72** 重编码，降到约 5 MB。
注意内嵌后页面里的帧是 1024 宽，而所有坐标仍是原图 1920 尺度。

### 3. 候选框叠加与判定

从 `detect2` 读该帧全部框画上去并编号。标注者做两件事：

1. **指认佩戴者的两只手 A / B**。检测器没框到就手画，导出时记 `"drawn": true`。
   手画的框可能超出画面边界（实测累计 10+ 个，最远 y=1593 / x=1942），
   不影响判定，但页面该加 clamp。
2. **其余每个框判一次**：`other_hand` / `not_hand` / `unsure`（v2 新增，O 模式按键循环）。

**双向防护**：同一个框不能既被指认成手、又被判成 others。
124431 帧 680 出过一次（IoU 1.0，同时是手 A 和 `not_hand`）——
那会让这个事件在 benchmark 里同时是正例和负例，**永远赢不了**。
页面两个方向都拦：指认为手时清掉该框的 others 判定，已是手的框拒绝进入 others 循环。

### 4. 导出 JSON

schema 见 `docs/hand_gold_schema_v2.md`。两个容易忽略的字段：

- **`others_complete_frames`**：记录"这帧其余的框全判过了"。
  没有它，**「没有其他框」和「还没判」在数据里长得一模一样**。
- **`intervals`**：每只手的可见区间（可多段）。与 `anchors` 分开，
  因为手离开画面再回来是一只手的两段，不是两只手。

导出后跑 `python3 src/semhand/validate_v2_gold.py <gold>.json` 做六项检查，
其中包括上面那条矛盾检查。
