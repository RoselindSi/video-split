一条录像（`R26_0824_133848`），37 个抽样帧全标、零「不确定」。

## §1 主指标

```
手 A   可见 37 帧   轨迹 2 条   覆盖 73.0%   切换 1
手 B   可见 37 帧   轨迹 1 条   覆盖 43.2%   切换 0

被单一轨迹覆盖 >=50% 的手：0 / 2      >=80%：0 / 2
```

**两只手各自以不同的方式失败，这正是把它们分开看的价值：**

| | 碎片化 | 覆盖 |
|---|---|---|
| 手 A | **是**（2 条轨迹，`0` 与 `9`） | 是（缺 10/37 帧） |
| 手 B | 否（1 条轨迹） | **是**（缺 21/37 帧） |

手 B 没有碎片化问题 —— 它只有一条轨迹，**但那条轨迹只覆盖了它可见帧的 43%**。
这是「手在画面里而流水线没有任何 own 轨迹盖住它」，和碎片化是两回事，
而旧的 tid 级 gold 两者都看不见。

**接好碎片的上界**：即使把 A 的两条完美接起来，它也只到 73%，
过 >=50% 而不过 >=80%；B 接不接都是 43%。
**所以碎片化不是这条录像的主要缺口，覆盖才是。**

---

## §2 标注者被迫手画框的比例 = 检测器在 gold 上的缺口

```
手 A   10 / 37 = 27%
手 B    4 / 37 = 11%
```

页面只在候选框都不可用时才需要手画，而候选框直接来自 detect2。
**所以这个比例是检测器在人确认的手上的缺口**，而且是无偏的 ——
gold 不受检测器召回限制，正是因为留了手画这条路径。

27% 与手 A 缺的 10/37 帧量级一致，提示手 A 的覆盖缺口主要是**检测层**的，
不是判定层的。

## §3 两个方法学结果

**① anchor 盲区 0 条。** 步长 10 在这条录像上够密，没有碎片因为「没盖住任何
anchor 帧」而对指标不可见。这验证了从 R0 的帧数分布推出来的那个密度。

**② 污染 2 条（tid `4` 与 `10`）。** 它们盖住了 anchor 帧但与两只手都不匹配 ——
即被判为 own=1 却不是佩戴者的手。与另一条录像上看到的裸臂那一例同类。

## §4 一个以危险方式失败的 bug，已修

第一次跑出来是「5 条轨迹**全部**是污染、两只手覆盖 0%」。

真因是文件名：代码按 `<rec>.csv` 找 detect2，而我的本地副本叫
`<rec>.detect2.csv`，`os.path.exists` 为假 → 框全是 `None` → 算不了 IoU →
每条轨迹都匹配不上 → **输出一个看起来像「系统彻底失败」的、自信的错误答案。**

**缺输入不该静默继续。** 现在 `read_tracks` 在 detect2 不存在时直接停并说明
为什么；入口也接受两种命名。

这类错误在这个项目里是惯犯（`--data` 非 append、暴露率分母、封顶被关、
fps/stride、删除没执行却报成功）—— 都不报错，只让数字静默偏掉。

## 这个差异指向检测，不指向跟踪逻辑

```
122009   手画框 0%      检测密度 2.54 /帧   两只手满分
133848   手画框 27%/11% 检测密度 1.78 /帧   两只手失败
```

「手画框」是标注者在候选框都不可用时才用的路径，而候选框直接来自 detect2，
所以它是**检测器在人确认过的手上的缺口**，无偏。

两条录像上它与结果完全同向，而且机制说得通：`133848` 的手 B **没有碎片化问题**
（只有 1 条轨迹），它的失败纯粹是那条轨迹只覆盖了 43% 的可见帧 ——
手在画面里而输出里没有框。**那是检测缺口的定义，不是关联算法的缺陷。**

**n = 2，所以这是一个假设不是结论。** 它的检验是现成的：第三条
（`R26_0824_121025`）的标注页已经发出，它的检测密度可以先算出来，
于是这条假设在标注之前就有一个可以写下的预测。

## §A 第三条打破了 n=2 时的故事，而打破的方式有用

`121025` 覆盖 94.4% / 100%，却碎成 3 条和 2 条 —— **盖住了但没追住**。
这是第三种模式，n=2 时看不到。

**所以我在 n=2 时写的「差异指向检测，不指向跟踪逻辑」太强了。**
两种失败都存在，而且可以分开计数：

```
只有覆盖问题  1 只手      只有碎片化  2 只手      两者都有  1 只      都没有  2 只
碎片化但覆盖 >=90% 的手：121025 的 A 和 B  <- 纯关联失败，检测没问题
```

## §B 事前写下的那条规则，两个输入打架，结果判了胜负

规则在收到第三条 gold 之前写在对话里：「密度接近 2.5 且手画框少 → 预测满分；
密度接近 1.8 → 预测失败」。而 `121025` 的两个输入指向相反：
密度 1.73（像失败的那条），手画框 6%/0%（像满分的那条）。

```
手画框   完全预测覆盖率，6 只手无例外
         27% / 11%  ->  覆盖 73% / 43%
         ~0%        ->  覆盖 >=94%
检测密度 完全不预测
         121025 密度最低 1.73，覆盖却 94-100%
```

**手画框是检测器在人确认过的手上的缺口，密度是它在整幅画面上的产量。**
前者预测覆盖，后者什么都不预测 —— 这正是「分母要选对」那条教训的又一次。

## §C 两种读法的差距现在是可量化的

你当初把读法 A / B 的选择推后到看数据。数据现在说：

| 覆盖阈值 | 读法 A（单一轨迹 + 覆盖） | 读法 B（只要覆盖） |
|---|---|---|
| >=50% | **2/6 = 33%** | 5/6 = 83% |
| >=80% | 2/6 = 33% | 4/6 = 67% |
| >=95% | 2/6 = 33% | 3/6 = 50% |

**读法 B 下系统已经不差（>=50% 时 83%），读法 A 下只有 33%。**
这和 R0 时从轨迹数推出的判断一致，但现在是在手这个单位上量出来的。
