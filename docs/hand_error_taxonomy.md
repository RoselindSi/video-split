窗口判决（`c4b0488`）之后不再调参数，先把缺陷归类。要求是**互斥、穷尽、
数目对得上** —— 否则就只是一组标签。

脚本：`src/semhand/hand_error_taxonomy.py`
结果：`results/semhand/hand_gold/error_taxonomy_w{30,150}.json`

## §0 先纠正一处框架：「轨迹断了要 merge」不是独立于窗口的一类

把 tid5 和 tid12 接起来**正是** `track_join` 在做的事，窗口就是它的参数。
所以「fragmented same hand → track merge」和「window tuning」不是两个轴，
是同一个轴的两头。真正的问题不是「窗口修不了断裂」，而是
**断裂里有多少是单纯隔得远、有多少是放宽之后候选不唯一**。

这只能数出来。数出来是这样：

| 同一批 42 处事件 | 窗口 30（旧） | 窗口 150（冻结后） |
|---|---|---|
| 流水线实际已接上 | 12 | 12 |
| 该窗口下会接上 | 0 | **3** |
| 被窗口卡住 | **16** | **1** |
| 几何分不开（候选不唯一） | **12** | **24** |
| 时间重叠（重复轨迹） | 2 | 2 |

**那 16 处「被窗口卡住」里，放宽之后只有 3 处真的接上，12 处变成了歧义。**

所以「被窗口卡住」在当前设置下是一个**近因**，八成是歧义戴着窗口的面具。
这也正是我自己在 `4c72f0f` 里犯过、在 `e0edb4b` 里更正过的错误 ——
只测了先撞上的那道门，没测放宽之后会撞上哪道。

## §1 帧级：丢的帧 100% 是检测，关联一帧都没丢

单位 = 「这只手可见的抽样帧」，519 个。

| 类别 | 帧数 | 占比 | 含义 |
|---|---|---|---|
| held | 467 | **90.0%** | 被唯一正确的轨迹持有 |
| held_duplicate | 5 | 1.0% | 被两条同属这只手的轨迹同时持有 |
| miss_no_detection | 3 | 0.6% | 那一帧一个框都没有 |
| **miss_box_elsewhere** | **44** | **8.5%** | 有框但没有一个是这只手 |
| miss_box_unassigned | **0** | **0.0%** | 有正确的框却没归到这只手 |

**丢失合计 47 帧（9.1%），其中 47 处全部是检测器没把框放到这只手上，
关联一帧都没丢。**

`miss_box_unassigned = 0` 是个强陈述：从来没有出现过
「框在正确位置、却没有任何归属这只手的轨迹持有它」。
也就是说 —— **只要检测器把框放对了，关联就一定接住了。**

## §2 身份级：断裂 71%，而且是另一回事

单位 = 「本该接上」的处数（一只手由 n 条轨迹持有 → n−1 处），42 处。

当前部署状态（流水线实际跑出来的）：**12 处接上，30 处没接上（71.4%）**。

两张表的分母不同，**不能相加**。帧级问「丢了多少帧」，身份级问「身份断了几次」。
一只手可以帧级满分而身份级很差：`134748` 手 A 覆盖 100% 却碎成 2 条；
`145525` 两只手都是 100% + 单一轨迹；`100512` 手 A 覆盖 94.1% 碎成 3 条。

## §3 所以这条线的两个瓶颈是分开的，方法也不同

| 瓶颈 | 量级 | 现象 | 要什么 |
|---|---|---|---|
| **检测器漏这只手** | 帧级 9.1%，占全部丢帧 **100%** | 手在画面里，框没放上去 | 检测器本身（小框、边缘、遮挡）—— 不是关联问题 |
| **身份断裂** | 身份级 **64–71%** 没接上 | 覆盖可以很好，但碎成 2–6 条 | 见下 |

身份断裂按冻结窗口 150 再分：

| 类别 | 处数 | 占没接上 | 要什么 |
|---|---|---|---|
| **几何分不开** | **24** | **89%** | 外观 embedding / 手势 / 运动模型 / 左右手先验 —— 中心距与框宽不携带区分信息 |
| 重复轨迹 | 2 | 7% | duplicate suppression / track-level NMS。**merge-only 结构上做不了**：两条同时存在，要决定留谁、身份史怎么合、ownership 怎么合 |
| 还被窗口卡住 | 1 | 4% | 一处 201 帧的超长离场，不值得为它放宽 |

**窗口已经不在这张表的主位上了。**

## §4 下一步的顺序

```
1. 歧义消解（24 / 27 处）        <- 唯一值得做的大头
     需要几何之外的证据：外观、handedness、间隔前两只手各自在哪
2. 重复轨迹抑制（2 处）           <- 量小但 track_join 结构上做不了，要单独一步
3. 检测器对「自己的手」的召回      <- 帧级丢失的全部来源，与关联正交
4. 窗口                          <- 已冻结，不再动
```

第 1 和第 3 是**正交**的两条线：帧级丢失全是检测，身份断裂全是关联，
`miss_box_unassigned = 0` 证明两者没有交叉项。可以分头做、分头量。

## §5 一个必须保留的限制

这十条的帧来自 `nothand_bank_e2e10`，是模型派生的子集，
`present_rate` 只有 0.55–0.93（见 `hand_gold_sampling_frame_defect.md`）。
缺的帧基本是检测器没出框的帧 ——
**所以 §1 里 9.1% 的帧级丢失率是下界，真实的检测漏报比这高。**
身份级的结论不受这个影响（它数的是轨迹之间的断裂，不是帧的有无）。
