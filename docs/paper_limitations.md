# Limitations：三条的处理（2026-10-12）

三条性质不同，所以处理方式不同。两条已经从「坦白」升级成「测量」，
而测量结果**和我原先的断言相反**；第三条是可审计的缺口，不是已丢的数据。

---

## ① CPR 那个点 → 已测量，而且暴露出 y 轴本身依赖我选的窗口

**原先打算写的：** 「一个 scenario 落在联合区间里，但它的录像长度与我们的
180s 窗口单位不匹配。」这把问题归给了数据。

**实测（`results/auditor/b2_egoexo/sensitivity/`，三个窗口长度 × 同一个 classify）：**

| scenario | 60s 命中 / 分叉 | 90s | 180s |
|---|---|---|---|
| First Aid - CPR | 78.4% / 2.54% | 79.4% / 2.94% | 77.3% / 3.16% |
| Making Cucumber & Tomato Salad | 65.3% / 2.27% | 64.0% / 2.45% | 57.4% / 2.63% |
| Cooking Noodles | 14.4% / 0.92% | 17.5% / 2.36% | 19.8% / **7.05%** |
| Covid-19 Rapid Antigen Test | 21.9% / 0.38% | 16.6% / 0.84% | 11.6% / **4.47%** |

落在联合区间（命中 ≥50% 且 `|S|≥2` ≥3%）的 scenario：

```
60s   无
90s   无
180s  First Aid - CPR（且它的 3.16% 只比 3% 的门槛高一点）
```

**两个结论，第二个比第一个重要：**

**(a) CPR 的复现率对窗口单位稳健**（78.4 / 79.4 / 77.3），所以它的高复现**不是**
窗口造成的假象。原先那句「录像长度与窗口单位不匹配」是错的归因。

**(b) 分叉那条轴强烈依赖窗口长度，复现那条轴不依赖。** 几乎每个 scenario 的
`|S|≥2` 都随窗口单调上升（Cooking Noodles 0.92 → 2.36 → 7.05；
抗原 0.38 → 0.84 → 4.47）。机制是机械的：窗口越长，每窗口决策越多，
前驱被离开两次的机会越大。

**所以主图的 y 轴不是数据集的性质，是（数据集, 窗口单位）的联合性质。**
任何关于 branching 稀缺的陈述都必须写明窗口单位。而联合区间的占据情况
在 60s 和 90s 下是**空的**，在 180s 下只有 CPR 且擦着门槛 ——
**「稀疏占据」这个说法本身就是窗口和门槛共同决定的，不是一个稳定事实。**

**正文怎么写：** 不写「联合区间稀疏占据」这种像结论的话，写
*在我们采用的 180s 窗口单位下，19 个点里有 1 个越过两条门槛，且其分叉率紧贴门槛；
缩短窗口后无点越过。分叉轴随窗口单调变化，因此该轴上的任何稀缺性陈述都是
相对于窗口单位的。* 并把三个窗口的表放进附录。

**不为 CPR 再开采集** —— 它的位置已经在三个窗口下测过了。

## ② `step_unique_id` 的偏置 → 用数据集自带字段测不出来，而人工探针指向反方向

**原先打算写的：** 「`step_unique_id` 索引『第几步』而不是『哪个状态』，
回到同一个物理状态会拿到新 id，所以它在构造上压低复现率。」
这是一个**断言**，我把它当成已知偏置写进了 Setup。

**实测一：数据集提供三种编码，换一个也测不出差别。**
把状态身份从 `step_unique_id` 换成 `step_name`（按名字合并，
这应该**高估**复现率），16 个 scenario 的命中率**逐个完全相同，全部 +0.0 pp**。

也就是说在这些窗口内，两种编码的划分是等价的 —— 同一个名字总是同一个 uid。
**所以这个偏置用数据集自己的字段无法测量**，不能当成已知量写进 Setup。
（这不证明偏置不存在：如果 taxonomy 本身就没有「回到做过的事」这个概念，
两种编码会以同样的方式失效。但它确实意味着我手上没有能给它定界的工具。）

**实测二：唯一的人工探针把方向反过来了。**
修车族，同一个任务族两种粒度：

| | 窗口 | S 非空 | 命中 \| S 非空 |
|---|---|---|---|
| keystep 粒度 | 30 | 13.0% | **52.4%** |
| 人工动作级 + 强制 id 复用 | 10 | 23.6% | **15.4%** |

人工重标让「前驱曾被离开过」的比例**升高**（13.0 → 23.6%），
却让可达集的命中率**大幅下降**（52.4 → 15.4%）。
这和「强制 id 复用会恢复被压低的复现」正好相反，而且原因第三轮已经查清：
动作级造出了大量过渡状态（`拿工具`），它们的后继五花八门 ——
**制造出来的是低质量的复现。**

（两组窗口不同（30 对 10），所以这是同族不同样本的比较，不是配对比较。
但方向差这么大不是抽样能解释的。）

**正文怎么写：** 把这一条从 Setup 的「已知偏置」移到 Limitations 的
「无法定界的量」：*我们用 `step_unique_id` 作为状态身份。它可能与人类对
「回到同一个状态」的判断不一致，但数据集提供的两种替代编码给出逐个相同的结果，
因此该差异无法用数据集自身测量；而我们唯一的人工重标探针在同一任务族上
把复现质量推向了相反的方向。*
