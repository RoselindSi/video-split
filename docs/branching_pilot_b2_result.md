# B2 结果：NO-GO（2026-10-11）

判据冻结于 2026-09-28，写在 `src/auditor/boundary/b2_yield.py` 里，这一轮一个字没改。
20 个 Ego-Exo4D 烹饪窗口全部粗标完成（标注者 r1，`status=final` 20/20），
评估器直接打印 **NO-GO**。

```
① 出度 >= 2 的录像        3 / 20
② prefix-valid G-branch   0（每条 0.00）     需要 >= 15（宽）/ 20（严）
③ G-novel                 4
④ 可达集大小 |N+|         无（没有 G-branch）
```

四条判据全部未过，不是其中一条擦边。

## 失败在哪一个子句上

G-branch 的定义不是「出度 ≥ 2」。`branch_mine.classify` 要求在**严格前缀下**同时成立：

```
|S| >= 2            前驱已经被观察到走向两个不同的后继
|S| < |candidates|  可达集必须真的排除掉东西，否则约束是空的
n_seen >= 3
```

54 个决策的 `|S|` 分布是 **{0: 50, 1: 4}**。`|S| >= 2` 的决策数是 **0**。

所以失败不是「转化率低」，而是**机会根本不存在**：20 个窗口里只有 4 个决策的前驱
曾经被离开过，而那 4 次每个前驱都只被离开过一次。没有任何一个状态在一条录像内
被观察到走向两个不同的后继——判据一那句写死的话，一次都没有发生。

这是同一个分布事实的**第四次**独立测量（此前 2 / ~5 / 0）。

## 唯一能推翻这个测量的检查：粒度

粗标把 3 分钟压成中位 3 个状态。如果 branching 存在但被标注粒度抹掉了，那 0 就是
我的测量单位造成的地板效应，而不是域的事实。预筛此前用 Ego-Exo4D 自己的
`step_unique_id` 预测这一族约 0.43/窗口，和人工的 0.00 不一致，必须查。

**同样 20 个窗口，两个粒度跑同一个分类器：**

| | 人工粗标 | Ego-Exo4D keystep |
|---|---|---|
| 每窗口状态数（中位） | 3 | 12 |
| 决策数 | 54 | 240 |
| `\|S\|` 分布 | {0: 50, 1: 4} | {0: 202, 1: 29, 2: 8, 3: 1} |
| `\|S\| >= 2` | **0** | **9** |
| G-branch | 0（0.00/窗口） | 9（**0.45**/窗口） |
| G-novel | 4 | 34 |

两件事因此确定下来：

**一、预筛没有错，人工粗标也没有错。** 0.45 和预筛事前算出的 0.43 几乎重合，
分歧全部由粒度解释。细粒度确实能挖出 branching——但只能挖出 9 个，仍然是个位数，
仍然低于宽端 15，每窗口 0.45 也低于宽端 0.5。**在能拿到的最有利粒度下，这批数据
依然不过 Go。**

**二、细粒度把图变得更有害，不是更有用。** 在 S 非空（图对下一步有意见）的决策里，
gold 真的落在可达集里的只有：

```
人工粗标      0 / 4    （ 0%）
keystep      4 / 38   （11%）
```

G-novel 以 34 : 9 压过 G-branch。作为 hard constraint，这个前缀图在它开口的场合里
有约 89% 的时候会把正确答案锁在外面。

**这个 11% 只属于 Ego-Exo4D，不要外推。**（2026-10-11 更正：初稿把它写成了
Experiment D 在线失败的机制，那是错的。）内部数据集上同一个量是反的：

| | S 非空占比 | S 非空时 gold 在 S 里 |
|---|---|---|
| 内部数据集（49 录像 / 322 决策） | 205/322 = **64%** | 196/205 = **95.6%** |
| Ego-Exo4D keystep（240 决策） | 38/240 = **16%** | 4/38 = **11%** |

Experiment D 和 ladder 跑的都是内部数据集（同一批 322 决策 / 49 录像），
那里图开口时几乎总是对的。所以 D 的 `full = −0.118` **不是**因为可达集里没有答案，
它就是身份估计的误差传播：错的 identity → 查错的 successor memory。
这两件事必须分开记，否则会把一个域的性质贴到另一个域的失败上。

**两个数据集是以相反的方式失败的，而两种失败都不给方法留空间：**

- **内部数据集：状态可靠地复现，但几乎不分叉。** S 非空 64%、命中 95.6%，
  所以图确实有效——但它退化成单条目缓存（`support − cache = +0.003`，CI 跨零），
  因为 `|S| >= 2` 只在 11/322 = **3.4%** 的决策上发生。
- **Ego-Exo4D：名义上更容易分叉，但状态几乎不复现。** S 非空只有 16%、命中 11%，
  所以图很少开口，开口时通常是错的。

也就是说：**可以有复现而没有分叉（内部），或者有名义分叉而没有复现（Ego-Exo4D），
但拿不到两者同时成立。** 这比「数据集里 branching 偏少」更准确，也更难被反驳。

一个必须留给下一批回答的问题：Ego-Exo4D 那 11% 有多少是**器具造成的**。
`step_unique_id` 是「第几步」而不是「哪个状态」，回到同一个物理状态会拿到新 id，
所以 keystep 粒度在构造上就压低复现率。内部数据集的 95.6% 恰恰来自标注合同里
「回到做过的事要选回原代号」这一条。人工按动作级粒度标一遍，是唯一能把
「真的不复现」和「id 不复用」分开的办法。

## 这批数据能和不能证明什么

必须说清楚，否则这个结论会被当成比它实际更宽的东西：

**能：** 公开第一视角烹饪数据（Ego-Exo4D，7 个机构、20 个 take），在从 3 个状态到
12 个状态的任何粒度下，都不提供足以检验结构推理的 branching。预筛、人工标注、
两种粒度四个口径一致。

**不能：** 这不是「没有任何任务形态提供 branching」。spec 第 28 行写的是
**「这个池子缺的是任务形态本身，所以 pilot 必须新拍」**，而我没有新拍，
用的是外部便利样本，而且 Ego-Exo4D 烹饪仍然是**照菜谱推进**——正是杀死内部
471 条池子和 EPIC 那一路的同一个结构性质。真正要的
diagnose-then-decide（排障、分拣、检查后决定）始终没有找到数据源：内部池子
排障 0 条、中断式 0 条；EPIC 60.2% 的分叉是 pick-up/put-down 的标注假象；
Ego-Exo4D 的自行车任务是规定好的拆装而不是先诊断再决定。

所以严格的表述是：**三条可获取的路线（内部池 / EPIC / Ego-Exo4D）都不包含这个
regime，而唯一剩下的选项是去拍一种我们至今无法获得的任务形态。**

## 决定

spec 里最要紧的那一行适用：

> **停止（硬性）**：如果刻意选了 branching-native 任务之后，仍然只有个位数
> G-branch，就直接停掉 Graph 作为当前的主方法方向。

0（粗标）和 9（keystep）都是个位数。按 spec，**停掉 Graph 作为主方法方向**，
并且**不要变成「再拍 20 条看看」**——B2 本来就是最后一次低成本 feasibility test，
它的作用正是在这里生效。

可以写下来的口径仍然是 2026-09-28 冻结的那个：
**近确定性的流程导致 branching 不可识别**，不是「Graph failed」。现在它多了一个
跨域的外部验证，以及一个新的、更强的附带结果：在这种流程里，前缀图作为硬约束
会主动损害预测（S 非空时只有 11% 命中）。

## 标注数据本身的几处记录

不影响判决（判决由 `|S| >= 2` 一次未发生决定，对这些都不敏感），但入档：

- `minnesota_cooking_031_2_w000002`：声明了代号 B 但 segments 里从未使用，
  末段为 `?` → 链为 `AC`，2 个状态 1 个决策。像是建了 B 之后又改标。
- `georgiatech_cooking_14_01_2_w000863`：声明了代号 E，从未使用。
- 4 个窗口有末段 `?`（看不清）：minnesota、iiith_116、upenn_7_3、fair。
  `chain()` 按设计跳过 `?`。已逐条确认**没有**任何 `?` 夹在两个相同代号之间，
  所以没有发生静默合并。
- 2 个窗口整段单状态 → 0 决策：`sfu_cooking023_4`（48s）、
  `fair_cooking_07_2`（152s 标为单一「挑选并清洗食材」）。
- 窗口时长 48–182.5s，`windows()` 的 30s 下限和 180s 上限都没有被突破。
