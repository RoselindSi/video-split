# 碎片接续：对人工 gold 的判定

冻结于 2026-10-09。代码 `src/rig/track_join.py`，测试
`tests/test_track_join.py`，在流水线里是 stage 3b。

---

## 它要解决什么

对「OWNER 手轨迹稳定」这个目标，实测的瓶颈不是语义判断而是 tracker 碎片化：
两只手中位切成 **5 条轨迹**、**42%** 的轨迹有空洞，而错误集中在短碎片上
——**<10 帧 8% 判错 / 7.6% 帧级误糊**，**≥34 帧 0% 判错 / 0.66%**。

语义门能修的只占 2%（C 类轨迹 3 条），碎片化是它的 25 倍。

## 规则

只接**不存在疑问**的那一类：一条碎片结束后，窗口（30 帧 ≈ 5 秒）内、中心距
≤3 倍框宽的范围里**恰好只有一个**后继。52 条录像上，57.9% 的结束点没有任何
候选（手真的离开了），**31.8% 恰好一个**，10.3% 有多个。有多个时取最近的只是
把猜测包装成几何，所以不取。

**左右手标签不作为闸门**，这是测量不是偏好：这些接续里 21.6% 的 side 多数不
一致，初看像五分之一接错。但在一条**身份无疑**的碎片内部，4.4% 的帧就和自身
多数不一致、55.6% 的碎片至少翻一次，反推碎片多数 side 的可靠度约 0.88，单这
一项就能解释掉那 21.6%。拿一个自身 12% 不可靠的标签当闸门，是在丢掉好接续去
躲一个它看不见的问题。接续后用**合并整轨**重算 side——证据比任一碎片都多。

**时间重叠硬否**：一只手不可能同时在两处。原审计只看正间隔，所以这条从未被
触发过，但只因输入恰好被过滤而正确的规则不算规则。

---

## 判定：对 fresh20 的 291 条人工 gold

接续如果把一条 OWNER 碎片和一条 OTHER 碎片接起来，那是**可证伪的错误**，
不需要人看图。

### 顺序决定结论

| | 未前置过滤 | **前置过滤后（部署顺序）** |
|---|---|---|
| 碎片 | 321 → 235（−26.8%） | 139 → 98（**−29.5%**） |
| 合并组 | 58 | 28 |
| 跨类别合并 | 15（25.9%） | 5（17.9%） |
| **其中 owner↔other** | **1** | **0** |

**部署顺序下零次把自己的手和别人的手接到一起**，而那是对本目标唯一致命的
错误。剩下 5 组冲突全部是 `not_hand` 混入，即上游 hand-ness 未滤净的残留，
不是身份判错。

### 第一版测错了顺序

第一次在 `/storage/fresh60` 上跑，那是**没做过 hand-ness 前置过滤的老跑**，
得出 25.9% 跨类别。但部署时 `track_join` 拿到的是 stage 3 的输出，而 stage 3
的 `--handness_boxes` 在 tracker **之前**就把非手摘掉了。`fragments()` 确实
过滤 `not_hand` 列，但那是**该跑自己的** hand-ness 判定——老跑没有，所以喂
进去的轨迹里本来就混着非手。

**所以 stage 3b 的位置不是偏好，是这组数字决定的：只在前置过滤之后跑。**

### 搬标签那一步也验了

两跑的 tid **不可比**（过滤改变了进 tracker 的框集，同一个 tid 可能是不同的
手），所以不能按 tid 直接对 gold。改按几何匹配（IoU ≥0.5、帧重叠 ≥30%、要求
唯一）搬标签：**139/139 唯一匹配、零歧义**，才敢用。

---

## 性质，由测试保证

`tests/test_track_join.py` 11 条全绿：只并不拆、时间重叠硬否、传递闭包、
窗口外不接、距离外不接、两个候选时不动、`not_hand` 行不参与、其他列原样、
side 按合并整轨重算、幂等。

### 幂等是测出来的，不是断言的

第一版 docstring 写着「running it twice is the same as running it once」，
**不成立**。性质测试给出反例：三条碎片按 10 帧间隔排列时，第一条看得见两个
候选、正确地不动；但第二、三条并成一条之后它就只剩一个候选，**第二遍会多并
一次**。

改成**在一次调用内迭代到不动点**，让幂等由构造保证。这个迭代**改变了语义**，
而且是故意的：一个端点的两个候选如果本就是同一只手，那「后面接谁」就只有一个
答案——因为备选相同而消失的歧义，从来不是身份上的歧义。

## 在流水线里

stage 3b，位于 stage 3（过滤后重跟踪）与 stage 4（post_pass）之间。放在
post_pass 之后就要去调和在碎片上形成的裁决，而那正是这一步要消除的东西。

实测（4 条录像，metadata 模式）：**碎片 64 → 46（−28.1%），耗时 0.1 秒**，
对整体墙钟没有影响。降幅与 gold 录像上的 −29.5% 一致。

`--no-join` 可关。默认开，因为对本目标实测的代价是零。
