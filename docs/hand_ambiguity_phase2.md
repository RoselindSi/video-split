# Phase 2（加入 DINOv2 外观）：判据通过，但不是靠外观单独通过的（2026-10-13）

判据与 Phase 1 **完全同一条**（事前写死，未改）：
**unassigned 负例一个都不并错，且召回 >= 30%**。阈值挑选规则也与 Phase 1 相同，
否则两期不可比。

脚本：`src/semhand/ambiguity_phase2.py`　结果：`results/semhand/hand_gold/phase2_appearance.json`

---

## §1 结果

留一录像（8 条有可打分歧义点的录像，111 对，正 57 / 负 54）：

| 打分 | 召回 | 误并自己的另一只手 | **误并未归属** | 判据 |
|---|---|---|---|---|
| 几何 `s_plain`（Phase 1 基线） | 35.1% | 0 | **1** | 未通过 |
| 外观 `cos_mean` 单独 | **63.2%** | **8** | **1** | 未通过 |
| 外观 `cos_junc` 单独 | 35.1% | 1 | **1** | 未通过 |
| **几何 + `cos_mean`（逻辑回归）** | **54.4%** | 1 | **0** | **通过** |
| 几何 + 两个外观（逻辑回归） | 47.4% | 1 | **0** | 通过 |

**外观单独不行。** 它召回最高（63.2%）但把自己的两只手并错 8 次、未归属并错 1 次。
**是几何把它拉住的** —— 几何负责「位置上说不通就别并」，外观负责「位置说得通时，
这到底是不是同一只手」。两者缺一都不过判据。

---

## §2 接头假设是错的

原本预期接头处（A 末尾 k 帧 vs B 开头 k 帧）相似度最可靠，因为光照姿态最接近。

```
决策点内 AUC
  cos_mean （整轨均值）   0.866
  s_plain  （几何）       0.821
  cos_junc （接头）       0.719     <- 最差
```

而且把 `cos_junc` 加进组合反而**变差**（54.4% → 47.4%）。

原因大概是接头处正是最糟的取样点：轨迹会断，往往就是因为那里遮挡、运动模糊、
框被截。整轨均值跨越了外观变化，但每一帧都比接头那几帧干净。

---

## §3 外观学到的是实例，不是场景

所有 pair 按构造都在同一条录像内，所以不可能靠「哪条录像」作弊。更强的检验是
看它能不能分开**同一个人的另一只手**（同一帧、同一光照、同一肤色、同一袖子）：

| 对比 | `cos_mean` AUC |
|---|---|
| 同一只手 vs **自己的另一只手** | **0.793** |
| 同一只手 vs 未匹配上（别人的手/非手） | 0.891 |

中位相似度：同一只手 0.781、自己的另一只手 0.620、未匹配上 0.601。

**0.793 这一项说明它拿到的是实例级信息**，不是「这是手/这是那个场景」。

---

## §4 必须说清的三个限制

**一、五个变体里报了最好的两个。** 判据是事前写死的，但「用哪个外观特征、
怎么组合」没有事前指定。看到五个结果之后挑一个，是在结果上做选择。
所以能说的是「**加入外观之后判据可以被满足**」，不能说「54.4% 是可部署的数字」。

**二、8 条录像 / 111 对。** 10 条里有 2 条没有可打分的歧义决策点。
按录像聚类的 bootstrap 正在跑，差值的区间出来之前，54.4% 对 35.1% 只是点估计。

**三、不能用 `src/semhand/embed.py` 那套。** 它是 Qwen3-VL-Embedding，提示词写的是
「Represent what this hand is doing」—— 编码的是动作语义。两只手做同一件事会被判成
相似，**正好是这里最危险的负例**。这一步必须用自监督的实例级特征。

## §5 跑法

```
DINOv2 ViT-S/14（timm vit_small_patch14_dinov2.lvd142m，384 维，输入 224）
每条轨迹在自己的帧上均匀取最多 16 帧，裁剪边距 0.15，L2 归一后取均值再归一
实际拿到视图 826/882 = 94%；没有一条轨迹是零视图
```

服务器上 huggingface.co 不通、pypi 通，权重走 `HF_ENDPOINT=https://hf-mirror.com`。
timm 用 `--no-deps` 装，不动生产 venv 的 torch。

## §6 还没解决的

- **35 个决策点里 2 个没有正例**：真后继被窗口或距离挡在候选集外。
  任何消解器都救不了，那是召回问题。
- **2 处时间重叠**（tracker 把一只手同时放成两条）：merge-only 结构上做不了。
- 召回 54.4% 意味着 57 处里仍有 26 处没并上。

# 下游效果：才是真正的目标量（2026-10-13）

脚本：`src/semhand/ambiguity_downstream.py`　结果：`results/semhand/hand_gold/phase2_downstream.json`

## §7 pairwise 召回不是目标函数

合并有**传递性**：手 A 若碎成 t1/t4/t6，从 t1 的末尾看过去 t4 和 t6 可能都是候选，
从 t4 的末尾看过去 t6 也是候选 —— 但并了 t1-t4 与 t4-t6 之后，**t1-t6 自动成立**。
它仍然被记成一个「漏掉的正例」，而实际上什么都没漏。

所以 57 个正例里有冗余，**54.4% 不等于「修好了 54.4% 的手」，
剩下的 45.6% 也不等于 45.6% 的工作没做**。唯一说得上话的是碎片数本身。

## §8 实测

基准 = 部署状态（`track_join`，冻结窗口 150）；之后 = 在它之上**叠加**消解器的合并。

```
单一轨迹持有的手：7 / 19  ->  12 / 19        （36.8% -> 63.2%）
没有任何一只手变差
```

五只手被修好：`133848` A/B、`134748` A/B、`015550` B 从 2-3 条降到 1 条；
另有 `100512` A/B（4→3）、`063732` A/B（3→2、5→3）部分改善但没到 1。

**合并 32 对，其中 31 对真是同一只手。唯一那一次误并是 `other_own_hand`** ——
自己的另一只手，隐私上无后果，只是少一个身份。**污染性误并 0。**

## §9 按录像聚类 bootstrap：方向一致，但区间碰到零

```
合并前 单一轨迹比例   36.8%   95%CI [+10.5%, +65.0%]
合并后 单一轨迹比例   63.2%   95%CI [+31.6%, +90.0%]
差                 +26.3%   95%CI [ +0.0%, +52.9%]
20000 次重采样里 97.1% 为正
```

**95% 区间的下界恰好是 +0.0%，没有排除零。** 97.1% 的重采样为正说明方向稳定，
但 10 条录像就是这个区间宽度的来源。所以这是**有提示性的，不是已确立的**。

要确立它需要更多录像，而不是更强的模型。

## §10 修掉的一个 bug

第一版报出三只手「合并之后组数反而变多」—— 而合并在数学上不可能增加组数。
原因是基准用 `join_to_fixed_point`（**迭代到不动点**），而「之后」只跑了一轮
`resolve(forced_pairs(...))`，两者不嵌套，于是「之后」并得比基准还少。
现在的做法是先按 base 把碎片折成组，再在**组**上叠加消解器的合并。

## §11 直接回答「剩下的失败是 candidate 还是 matching」

**在这 57 个正例里，candidate missing 按构造是零** —— 正例的定义就是
「候选集里的候选且是同一只手」，不在候选集里的根本不会成为正例。
所以 26 个漏掉的全部是 matching 失败（外观/几何分不开），不是候选生成失败。

候选生成的失败是**另一个已经量过的集合**：

- 2 个决策点**一个正例都没有** —— 真后继被窗口或距离挡在候选集外
- 42 处 should-join 里，有些压根没形成「候选 >= 2」的决策点

这两件事不能混在同一个分母里数。

# §12 裁剪边距消融（2026-10-13）

| 边距 | `cos_mean` AUC | `cos_junc` AUC | 端到端召回 | 误并自手 | 误并未归属 | 判据 |
|---|---|---|---|---|---|---|
| **0.00** | **0.904** | 0.765 | 40.4% | 0 | 1 | 未通过 |
| 0.10 | 0.877 | 0.727 | **54.4%** | 1 | 0 | 通过 |
| 0.15（现用） | 0.866 | 0.719 | **54.4%** | 1 | 0 | 通过 |
| 0.30 | 0.874 | 0.792 | 43.9% | 0 | 1 | 未通过 |
| 0.50 | 0.854 | **0.833** | 36.8% | 0 | 2 | 未通过 |

**「身份来自袖口/手臂而不是手本身」这个假设被否了。** `cos_mean` 的 AUC 随边距
增大基本单调下降（0.904 → 0.854）—— **裁得越紧外观信号越强**，身份在手里。

`cos_junc` 的方向相反（0.719 → 0.833），即接头处的比较确实需要更多上下文；
但它在每个边距上都不如 `cos_mean`，加进组合也一直是负作用。

## 但这个消融没能确立最佳边距

**AUC 与端到端判据互相矛盾**：pad=0 外观质量最好却没过判据。端到端数字在
36.8%–54.4% 之间摆动，这个幅度与「外观相对几何的全部增益」（35.1% → 54.4%）
同量级。

所以它确立的是另一件事：**端到端指标在 111 对 / 8 条录像上太吵，分不出边距**，
与 Phase 1 挂在阈值稳定性上是同一个原因。边距保持 0.15 不动
（改动没有依据），下一步是扩数据不是继续消融。
